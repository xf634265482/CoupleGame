# PVE 移动事件回放卡死修复设计

## 问题与目标

远征移动或自动结束回合后，`ExpeditionController._apply()` 会在
`apply.playEvents` 阶段等待移动动画完成。Cocos tween 的完成回调在微信真机上
可能因节点失效、动画被打断或调度异常而不执行；一旦对应 Promise 未完成，
`_apply()` 的 `finally` 无法执行，`_busy` 会永久保持 `true`，随后所有输入都被拦截。

修复目标是让每个移动事件的回放都在有限时间内结束，并在异常路径中恢复单位
可见性、销毁移动幽灵、释放 `_busy`。不改变 PVE 状态演算、移动规则或云端协议。

## 方案选择

采用“动画正常完成 + 独立硬超时兜底”的方案：

- 正常情况下继续按现有顺序播放每段移动动画。
- `_playMoveFx()` 的等待由调用层施加硬超时，不能只依赖动画对象内部的回调。
- 超时后强制清理该实体的移动幽灵并完成本事件，随后继续回放剩余事件。
- 清理函数保持幂等，正常完成和超时竞争时只结算一次。
- 超时记录诊断日志，但不向玩家弹出错误提示，以免正常游玩被技术信息打断。

不采用完全异步播放全部移动动画的方案，因为同一怪物可能在单批事件中连续移动，
并发播放会破坏路径顺序。也不只在 `_apply()` 外层释放 `_busy`，因为那会留下未清理
的幽灵节点和错误的单位可见性。

## 数据流与错误处理

`_playEvents()` 遇到 `MOVE` 时调用有界的移动回放。动画完成时走原有清理路径；
超过上限时，兜底路径调用 `_clearMoveGhost(entityId)`，恢复最终格可见性并完成等待。
无论哪条路径先发生，Promise 都只完成一次。`_apply()` 因而能够继续执行
`_afterApply()`，最终在 `finally` 中释放 `_busy`。

兜底只影响表现层，不回滚或重算已经由 core 生成的新状态。

## 验证

- 单元测试模拟 tween 完成回调缺失，验证移动回放在超时后完成。
- 验证超时清理恢复目标格可见性并删除幽灵记录。
- 验证正常完成与超时竞争不会重复完成或抛错。
- 运行 `npm run test:pve`。
- 真机复测连续移动、AP 耗尽自动结束回合，以及怪物连续移动；控制台应继续出现
  `apply.afterApply`，且后续输入可用。

## 文档同步

这是 PVE 表现层容错修复，不改变玩法规则。实现后在
`specs/260608-pve-destiny-expedition/design.md` 的客户端事件回放约束中补充：
移动动画不得无限阻塞状态应用链。
