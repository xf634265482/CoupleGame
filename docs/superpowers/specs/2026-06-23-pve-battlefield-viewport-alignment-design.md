# PVE 战场视口与第一章背景对齐设计

## 目标

修复第一章真机画面中运行时棋盘压住背景顶部石板、底部存在大块未利用黄土地的问题。通过同步调整固定战场视口、格子显示尺度与 `bg_pve_ch1` 环境分区，使棋盘和章节背景自然衔接。

## 范围

- `assets/scripts/pve/controllers/ExpeditionController.ts`
- `assets/scripts/pve/views/FogMapView.ts`
- `assets/resources/art/ui/pve/backgrounds/bg_pve_ch1.png`
- PVE 视觉设计文档

不修改地图逻辑尺寸、坐标、寻路、碰撞、迷雾规则、HUD 卡片、战报、玩家状态卡或底部按钮布局。

## 布局调整

### 固定战场视口

- 战场视口整体向下移动约 24 设计像素。
- 顶边必须落在背景顶部石板边框下方，运行时第一行格子不得压住石板。
- 战场视口底边下探到战报与玩家状态卡片的顶部附近，保留约 6–10 像素视觉间距。
- 2026-06-23 底部真机复测后，战场视口横向占满屏宽，不保留会露出背景的左右缝隙。
- 不再依赖左右草地与石板边框表达章节结构，避免不同手机长宽比的 Cover 裁切造成边框丢失。
- 玩家处于地图顶部、中部、底部时，视口在页面上的位置和尺寸必须保持不变。

### 后续章节背景制作锁定规范（必须复用）

这是一份**代码与美术共用的版式契约**。从第二章开始，背景绘制只能适配下列固定棋盘窗口；不得为了迁就某张新背景而修改棋盘窗口、格子尺度、HUD 或相机参数。

| 项目 | 锁定值 |
|---|---|
| 背景画布 | 竖屏 `576 × 1024`，不得裁切、拉伸或改比例 |
| 棋盘窗口顶部 | 画布自上而下 `16.8%`（约 y=172） |
| 棋盘窗口底部 | 画布自上而下 `77.5%`（约 y=794） |
| 棋盘窗口高度 | `60.7%`（约 622px） |
| 棋盘窗口横向 | `100%` 屏宽，左右**零缝隙** |
| 横向格数 | `5.5` 格可见宽度 |
| 镜头方式 | 仅移动棋盘内容；顶部、中部、底部均在同一固定窗口内显示 |

绘制分工固定如下：

- 顶部 `0%–16.8%`：章节主题展示区（天空、远景、建筑、阵营元素），最底部以横向石板/地形边缘收口。
- 中部 `16.8%–77.5%`：完整、连续、无独立棋盘框的战场土地；必须横向铺到画布左右边缘。只允许少量低对比细节，不能画会和棋盘格、单位、交互物竞争的主体元素。
- 底部 `77.5%–100%`：章节主题收尾区；战报与状态卡会覆盖其上部，因此重点元素应放在卡片下方及两侧可见区域。

制作流程：先以这三段百分比建立背景底稿和辅助线，再绘制章节元素；生成或改色后必须保持原始 `576 × 1024` 尺寸。任何审核发现上下比例、中央留白或左右铺满发生变化时，应只返工背景图，不得改 `ExpeditionController` / `FogMapView` 的视口参数。

为避免生成模型误判比例，后续章节必须同时使用 [棋盘模具](../../specs/260622-visual-upgrade-v1/references/pve-chapter-background-grid-template.svg)：其运行时等比生产尺寸为 `720×1280`，红框为战场开口（y=`215–992`），虚线按横向 `5.5` 格划分。模具仅用于生成参考和验收，绝不烘焙进最终背景。已生成的背景若上下石板偏离模具，应采用“顶部／中部／底部三段非破坏性校正”或返工原图，不修改游戏代码。

### 地图显示尺度

- 在不改变地图逻辑尺寸的前提下，将横向视野调整为约 5.5 格。
- 目标是提高角色、怪物和交互物的真机辨识度，并利用加长后的战场区域。
- 超出固定视口的地图内容继续由 `FogMapView._content` 镜头偏移展示。
- 不允许移动 `FogMapView._root`、地图父容器、HUD、战报或底部操作区来追踪玩家。
- 边缘安全补偿继续保证玩家和 Boss 不被裁掉。

## 第一章背景调整

- 保留已批准入库版本的顶部哥布林瞭望塔、旗帜、木栅与远景塔楼。
- 中央黄土地继续作为无格线、低细节、连续战场平面。
- 第一章不再叠加 787×442 的横向 `tile_floor_ch1`；该素材被强制填充正方形棋盘时会纵向拉伸，第一章直接使用章节背景的自然土地。
- 顶部黄土地起点与运行时棋盘顶边对齐，位于顶部横向石板边框之下。
- 中央黄土地的下边界延伸至战报与玩家状态卡片顶边，消除当前卡片上方的大块空白断层。
- 底部草地和小路从信息卡片后方开始，不侵入可见战场。
- 顶部章节带必须压缩，顶部横石板上移，避免第一行运行时格子与哥布林草地/石板重叠。
- 底部横石板必须上移，增加底部草坪与小路的可见高度，恢复章节收尾空间。
- 运行时战场窗口按真机红框像素固定对应屏幕自上而下约 16.8%–77.5% 区间。
- 镜头边缘钳制使用小数可见格数，不得向下取整后产生顶部空带或底部额外内容。
- 镜头中心移向地图下方时，棋盘内容必须反向向上滚动；`_content` 对 `cameraPos` 的 x/y 坐标均使用反向位移。
- 中央黄土地横向延伸到画布两侧，移除左右纵向石框、草带和碎石边框。
- 章节辨识集中在顶部哥布林营寨/塔楼与底部草地/小路，不再由两侧窄边承担。
- 不增加新的独立棋盘框、格线、角色、怪物、交互物或 UI。

## 验收

1. 第一行运行时格子完整位于背景顶部横向石板之下。
2. 棋盘底边与战报/玩家状态卡顶部衔接，中间无明显闲置黄土地。
3. 横向约显示 5.5 格，在清晰度和镜头滚动频率之间取得平衡。
4. 玩家位于地图上、中、下三处时，固定战场视口坐标不变。
5. 地图镜头只移动 `_content`，边缘玩家与 Boss 不被裁切。
6. HUD、战报、玩家状态和底部按钮布局无回退。
7. `bg_pve_ch1.png.meta` UUID 保持不变。
8. PVE 测试、TypeScript 检查和图片校验通过。
9. 玩家走到地图最底行时，最后一行完整位于战报上方，固定棋盘视口本身不移动。
10. 棋盘左右边缘与屏幕边缘贴合，不露出竖向背景缝隙。
