# 营地角色区：职业战斗属性预览

日期：2026-07-18  
范围：营地「角色区」展示；不改职业数值、装备公式、命痕结算规则。

## 背景

营地角色区目前只显示职业等级、经验与技法。玩家调配装备、命痕、职业时，无法直观看到「若用该职业 + 当前营地配置」会有多少攻击/生命等，调配反馈弱于装备台本身。

## 目标

在角色区每张**已解锁**职业卡上，预览该职业叠加**当前营地装备配置**后的战斗面板四项，方便对比后再切换职业或回装备台调整。

## 已确认决策

| 项 | 选择 |
|----|------|
| 展示字段 | 攻击、最大生命、护甲、射程 |
| 非当前职业 | 每张卡都显示「若选该职业」的预览 |
| 数字口径 | 营地配置预览（换装/换职保存后立刻更新）；生命用**最大生命**，不读局内残血 |
| 布局 | 在经验条与技法行之间加一行属性文案（方案 A） |

## 方案

### UI（`CampView._renderProfession`）

- 已解锁卡在经验详情下方增加一行，格式示例：  
  `攻击 48 · 生命 320 · 护甲 12 · 射程 1`
- 当前选中职业可用金色强调该行；其他已解锁职业用常规正文色。
- 未解锁卡：不显示属性行（保持现有「未解锁」态）。
- 卡片高度可略增，保证三张卡仍可滚动/完整可见；不新增独立总览条，不嵌局内角色面板。

### 计算（新建纯逻辑 helper，建议 `core/`）

新增例如 `previewCampCombatStats(profile, professionId)`：

1. 用与开战相同的装载逻辑，把 `profile.equipmentLoadout` + 背包实例转成 `RunPlayer.equipment`（复用/抽出 `toRunEquipment` 一类，避免复制粘贴漂移）。
2. 以 `professionBaseStats(professionId)` 为底，叠装备生命等，拼临时 `RunPlayer`（`hp = maxHp`）。
3. 用现有 `playerAttackPower` / `playerArmorPower`（及射程来源与局内一致）得到四项数字。
4. **不**读取楼层 `ExpeditionState` / 临时 buff / 残血。
5. 命痕：仅当其已进入上述「与开战一致的面板公式」时才影响数字；不在营地发明额外面板加成。

章节/平衡快照：若 `playerAttackPower` 需要 `balanceSnapshot`/`chapter`，取与「当前最高可挑战或 profile 语境下开战」一致的默认值，并在实现计划中钉死单一规则（避免营地与进层差 1 点）。

### 刷新

`CampController` 在职业切换、装备装卸、命痕变更等配置保存成功并 `refresh` 后，角色区重绘，三张卡预览一并更新。

### 文档

- 同步 `specs/260608-pve-destiny-expedition/design.md`（或永久楼层主文档中营地小节）角色区说明。
- `CALL_FLOW.md` 营地渲染链补一句属性预览。

## 非目标

- 不显示当前局内残血、灼烧/减速等临时状态。
- 不在角色区做穿甲/护盾/AP 等额外字段（本轮固定四项）。
- 不改切换职业的云端校验与保存协议。
- 不做「仅当前职业显示属性」或顶部总览条方案。

## 验收

1. 打开营地 → 角色区：三张已解锁卡均有攻击/生命/护甲/射程。
2. 当前职业卡有选中样式，属性行可见。
3. 装备台换武器/护甲后回到角色区（或同屏刷新后），三张卡对应数字变化，且差异符合职业基底差（如游侠射程通常更高）。
4. 切换职业后，仅「当前职业」标记移动；预览数字在同一套装备下仍按各职业基底分别显示。
5. 未解锁职业仍无属性行。
6. 挑战进行中进营地：数字仍为营地配置预览，不是楼层实况残血。

## 测试建议

- 单测 `previewCampCombatStats`：空装三职业基底；同装战士 vs 游侠射程/攻击差；换装后生命/护甲变化。
- 手工：营地角色区与新开一层进层后角色面板四项对齐（允许文档钉死的章节默认差异为 0）。
