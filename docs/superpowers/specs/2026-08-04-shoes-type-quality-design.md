# 鞋子类型分化与品质阶段

日期：2026-08-04  
状态：已确认方向（设计评审通过，待实现计划）  
关联：`specs/260608-pve-destiny-expedition/design.md`、`specs/260712-pve-persistent-floor-progression/equipment-catalog.md`、`assets/scripts/pve/core/EquipmentSystem.ts`

## 1. 问题

鞋子槽现有 17 件目录，但玩法几乎只有一条「档位阶梯」：

- `baseStat ≥1` 移速减耗 → `≥2` 揭示 +1 → `≥3` 首步免费 → `≥4` 仇恨缩小。
- 名字里的「软靴 / 战靴 / 铁靴」只是风味，同品质内无类型取舍。
- 品质差异主要是同一阶梯上的 roll 运气，而不是可感知的身份升级。
- `baseStat` 被当成档位（1～5），与装备目录「鞋主数值 = 最大生命」的口径冲突；UI 显示「档位」而非生命。

## 2. 目标

1. **类型有区别**：轻靴 / 战靴 / 铁靴三条分支，像武器剑/斧/矛一样可构筑选择。
2. **品质有区别**：白/绿薄基础；蓝起分支身份；紫专精；橙顶配 + 传奇。
3. **保留现有 17 个中文名**，只改归属、主数值区间与效果挂载方式。
4. **主数值回归生命**：鞋子 `baseStat` 与头盔一致，计入最大生命；类型效果走 implicit + 品质阶段表。

非目标（本轮不做）：

- 新增/删除鞋子条目，或重做整套装备经济。
- 给铁靴补橙装传奇（现有 3 橙挂轻/战）。
- 改命痕移动相关效果，或重做板甲移速税。
- 其它槽位（武器/甲/盔/饰）的再分化。

## 3. 核心模型

鞋子效果拆成两层，互不混用：

| 层 | 含义 | 成长方式 |
|---|---|---|
| 主数值 | 最大生命 | `baseStat` × 品质倍率 × 强化；白/绿即有薄生命 |
| 类型效果 | `shoes_light` / `shoes_war` / `shoes_iron` | 由**实例品质**查阶段表；不读旧档位阈值 |

品质节奏：

| 品质 | 感知 |
|---|---|
| COMMON / FINE | 只有薄生命，**无**分支机动/节奏/硬抗专精 |
| RARE | 分支身份开启 |
| EPIC | 本支专精加强；铁靴此时才出现明确代价 |
| LEGENDARY | 本支顶配 + 传奇独特 |

铁靴代价：**仅 EPIC / LEGENDARY** 附加「每回合首步移动 +1 AP」；不与板甲「每步 +1 AP」混为同一种税。COMMON / FINE / RARE 铁靴无硬代价。

## 4. 品质阶段表

### 4.1 轻靴 `shoes_light` — 机动与视野

| 品质 | 类型效果 |
|---|---|
| COMMON / FINE | （无） |
| RARE | 移动 AP -1；迷雾揭示半径 +1 |
| EPIC | 同上 + 怪物仇恨半径 -2 |
| LEGENDARY | 同上但仇恨 -3；再叠加传奇 |

### 4.2 战靴 `shoes_war` — 节奏与爆发

| 品质 | 类型效果 |
|---|---|
| COMMON / FINE | （无） |
| RARE | 每回合首次移动 0 AP |
| EPIC | 首步免费 + 移动 AP -1 |
| LEGENDARY | 同上 + 传奇（疾风：首步后首次攻击 +25% 等） |

### 4.3 铁靴 `shoes_iron` — 续航与硬抗

| 品质 | 类型效果 |
|---|---|
| COMMON / FINE | （无；仅同阶最高生命） |
| RARE | 地形伤害减免 1（若当层有地形伤） |
| EPIC | 地形减免 1 + **首步移动 +1 AP** |
| LEGENDARY | 地形减免 2 + 首步 +1 AP + 传奇（本轮无铁靴橙） |

同阶生命相对关系：**铁靴 > 战靴 > 轻靴**。轻靴用机动补短板；铁靴用生命与抗地形换机动。

## 5. 主数值区间

约为头盔同阶的 55%～70%。模板 `baseStatMin` / `baseStatMax` 按类型与目录品质写入；实例升品后仍用同名区间，再经品质倍率缩放（与现有装备规则一致）。

| 目录品质档 | 轻靴 | 战靴 | 铁靴 |
|---|---|---|---|
| COMMON | 10–14 | 12–16 | 15–20 |
| FINE | 20–28 | 24–32 | 30–38 |
| RARE | 32–42 | 38–48 | 48–58 |
| EPIC | 52–68 | 62–78 | 78–94 |
| LEGENDARY | 80–100 | 95–115 | — |

说明：现有目录无铁靴 LEGENDARY 模板；不新增橙装铁靴。若三合一把铁靴实例升到传说：原始 `baseStat` 仍用该名 EPIC 模板区间规则；**生效生命**继续走统一公式 `round(baseStat × 品质倍率 × 强化)`，即传说倍率 1.75 作用于同一原始值。不另开传说区间表。

## 6. 目录映射（17 名保留）

| 类型 | 装备名 |
|---|---|
| 轻靴 ×8 | 布靴、旅行皮靴、轻便皮靴、猎手软靴、游侠软靴、疾行套靴、飞燕步履、影踪战靴 |
| 战靴 ×6 | 皮靴、铁制战靴、精制战靴、英雄战靴、隐足战靴、疾风之靴 |
| 铁靴 ×3 | 沙地靴、精钢铁靴、猎风铁靴 |

归属约定：

- **隐足战靴** → 战靴（节奏线）；潜行专精只留给轻靴，避免身份串线。
- **影踪战靴** → 轻靴（传奇减耗贴机动）。
- **疾风之靴** → 战靴（传奇首步 + 首击贴节奏）。
- 铁靴仅 3 双：稀缺坦克鞋；升品仍走同名三合一。

每件模板增加 `implicit: shoes_light | shoes_war | shoes_iron`（实现时常量名对齐武器风格）。

## 7. 传奇对齐

| ID | 名 | 类型 | 效果（保留现有语义） |
|---|---|---|---|
| `leg_gale_boots` | 疾风之靴 | 战 | 每回合首步永久免费；首步后首次攻击伤害 +25% |
| `leg_swallow_steps` | 飞燕步履 | 轻 | 怪物警戒感知额外缩小 3 格（与轻靴仇恨减叠） |
| `leg_shadow_boots` | 影踪战靴 | 轻 | 每步移动额外 AP -1（下限 0，可与轻靴移速减耗叠） |

传奇效果在 LEGENDARY 品质阶段之上叠加，不替代类型阶段表（疾风的「首步免费」与战靴蓝阶段重叠时取「已满足」，不双重免单）。

## 8. 废止与 UI

废止：

- `SHOES_REVEAL_BONUS_THRESHOLD` / `SHOES_FIRST_MOVE_THRESHOLD` / `SHOES_STEALTH_THRESHOLD` 及 `shoesStealthReduction(baseStat)` 的档位语义。
- 鞋子 `baseStat` 作为「档位 1～5」的读法。
- UI 主属性文案「档位 x/y」。

改为：

- 主属性：「最大HP +当前/上限」（与头盔一致）。
- 详情额外展示类型名 + 当前品质已解锁的阶段效果列表。
- 白/绿鞋子详情可标注类型（如「轻靴」），并提示「稀有品质起生效分支效果」。

## 9. 战斗接入点（实现指引）

只改鞋子解析路径，复用现有钩子：

- 移动耗 AP / 首步免费 / 揭示：`MovementSystem.ts`
- 仇恨半径：`MonsterAI.ts`
- 地形伤害减免：已有 `fixed.terrainDamageReduction` 通道则挂铁靴阶段；若无则本轮实现时补读阶段表。
- 定义桥接：`EquipmentDefinition.ts` / `EquipmentProgression.ts`（废除鞋「档位」标签）。
- 模板源：`EquipmentSystem.ts` → `EQUIPMENT_POOL.SHOES`

权威玩法文档在落地后同步：`design.md` 装备节、`equipment-catalog.md`（鞋隐式与阶段表）。

## 10. 验收口径

1. 同品质下，轻/战/铁三双鞋在蓝及以上有可感知的不同专精；白/绿仅生命差（铁 > 战 > 轻）。
2. 穿蓝轻靴：有移速减耗与揭示，无首步免费、无铁靴地形减。
3. 穿蓝战靴：有首步免费，无轻靴揭示/潜行。
4. 穿蓝铁靴：生命明显高于同阶轻靴，有地形减，**无**首步 +1 AP 代价。
5. 穿紫铁靴：出现首步 +1 AP；与板甲叠加时为「首步更贵 + 每步板甲税」，而非双倍每步税。
6. UI 不再出现「档位」；生命与类型效果文案正确。
7. 三件传奇效果在对应类型橙装上仍可触发；旧档位阈值逻辑无残留生效路径。

## 11. 决策摘要

| 项 | 选择 |
|---|---|
| 分支数 | 三岔（对齐武器） |
| 身份 | 轻靴 / 战靴 / 铁靴 |
| 品质节奏 | 白绿薄基础 → 蓝起身份 → 紫专精 → 橙顶配 |
| 铁靴代价 | 仅紫/橙首步 +1 AP |
| 落地方式 | implicit + 品质阶段表（非逐件写死、非旧档位偏置） |
| 目录 | 17 名全保留，按 §6 映射 |
