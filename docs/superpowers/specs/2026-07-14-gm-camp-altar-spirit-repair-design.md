# GM、营地、祭坛与战士灵气爆发修复设计

日期：2026-07-14

## 目标

修复 GM 清空命痕与装备校验失败、营地命痕标题遮挡空槽、第一章第三层祭坛交互后不进入结算，以及战士灵气爆发对普通攻击无效果的问题。改动只影响 PVE 与 GM 工具，不改变其他职业的爆发规则。

## GM 清空营地资产

- `cloudfunctions/common/` 仍是唯一云端共享源码；完成后同步部署副本。
- 清空命痕与装备必须在服务端事务内读取并更新目标用户，避免“先写后查”期间被并发档案写入覆盖。
- 清空字段包括命痕收藏、装配、方案、装备背包、装备装配和命尘；保留楼层进度、职业熟练度和金币，符合 GM 按钮“重置命痕与装备”的现有语义。
- 若玩家存在活跃楼层挑战，清空操作同时终止该挑战并清理 `activeChallengeId`，防止旧挑战结算或续档把已清空资产写回。
- 事务返回写入后的档案作为校验依据，不再通过非原子的二次查询判断成功。

## 营地命痕布局

- 保持现有 8 个已装配槽、四列两行布局。
- 修正第二排槽位的 Y 坐标：行偏移只由 `_gridCard` 计算一次，调用方传入固定首行基准，不再重复减去一行高度。
- “已装配命痕”“拥有的命痕”、两排槽位、库存滚动区和“保存方案”各占独立纵向区域，边界之间保留间距。
- 增加纯布局断言或可测试的坐标计算，覆盖 720×1280 目标画布，确保标题、卡片和按钮包围盒不重叠。

## 第三层祭坛通关

- 最终战场状态是目标对账的权威来源。祭坛被消耗后，对固定守卫和祭坛召唤物统一检查：怪物已死亡或已不在战场时，从目标状态的存活 ID 中移除。
- 对账后若祭坛已摧毁、固定守卫清空且没有存活召唤物，目标立即转为 `COMPLETE`，生成且只生成一个 `FLOOR_CLEARED` 事件。
- 控制器继续沿用唯一 `_apply → _afterApply → _settlePersistentFloor` 链路显示“继续远征 / 返回大厅”弹窗，不新增第二套结算入口。
- 增加恢复态与丢失击杀事件场景测试，复现“祭坛消失但目标仍 ACTIVE”的历史故障。

## 战士灵气爆发

- 战士爆发“破阵”仍消耗满额灵气并强化下一次攻击。
- 若玩家未手动选择蓄力，下一次普通攻击自动按 1 级蓄力解析；若已选择 1–3 级蓄力，则沿用玩家选择。
- 爆发最多替玩家支付 2 点额外蓄力 AP，并提供现有 20% 额外破甲；伤害倍率、击退与横扫继续由实际蓄力等级和已解锁技法决定。
- 成功释放时提示明确写出“下一次攻击至少按 1 级蓄力生效”；攻击预览、实际 AP、伤害与爆发消耗必须使用同一解析结果。
- 增加普通攻击自动 1 级蓄力、手动更高蓄力、AP 不足和爆发只消费一次的测试。

## 验收

1. GM 清空命痕与装备返回成功，重新查询后相关字段为空；活跃挑战不会把旧资产写回。
2. 720×1280 营地命痕台中，两排空槽、两个标题、库存卡片和保存按钮互不遮挡。
3. 第一章第三层清空敌人后交互祭坛，祭坛消失并立即出现通关选择弹窗；恢复旧存档也能完成对账。
4. 战士满灵气释放爆发后直接普通攻击，按 1 级蓄力获得对应效果；手动蓄力仍可选择更高等级。
5. PVE 测试、云函数测试、类型检查、GM 构建和云端共享源码同步全部通过。
