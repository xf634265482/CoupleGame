# PVE 稳定性修复设计

日期：2026-07-14

## 目标

一次修复营地、远征关卡选择、战斗表现、掉落展示与 GM 重置的已知问题；不新增玩法，不新增怪物品类。

## 营地

- 删除“刷新”按钮；营地在每次打开时读取一次档案。
- 命痕台与装备台的分区标题使用独立纵向行，标题、格子、底部操作区之间保留固定间距，所有节点限制在面板边界内。
- 详情弹窗使用统一内容区与按钮区，关键信息无需滚动即可读完。

## 远征入口

- 关卡选择弹窗标题固定为“选择关卡”。
- 上一章、当前章节、下一章同排；不可进入的章节翻页按钮置灰。
- 层数按钮根据“已通关层数 + 下一可挑战层”可用性渲染；禁用按钮采用独立灰色填充、边框与文字色。
- 选择层数后的确认弹窗以关卡名称为标题，正文仅呈现该层胜利条件，按钮为“远征”“关闭”。

## 战斗与关卡

- 角色移动只复用 `FogMapView` 中唯一的玩家节点；开始新动画前取消旧动画并同步节点坐标，杜绝残影。
- 宝箱沿用既有实体节点与资源映射；资源缺失时使用可见的文字/图形后备表现，不显示红色占位块。
- 沿用 `CombatSystem -> LootSystem -> ExpeditionController._replayEvents -> PveToastView` 事件链，保证普通怪与精英怪的金币、职业碎片、装备等掉落都可见。
- 第一章第四层追击目标使用现有“哥布林哨兵”定义，不再引用传令兵专属怪物。

## GM 与数据

- 删除 GM 前端和服务端的命运树入口、展示与操作，不影响营地入口。
- “重置远征”以默认远征档案覆盖旧档案，清空等级、经验、命痕、装备、已装配方案及进行中的挑战数据。
- 云函数共享源码改动后同步到所有部署副本；GM 前端重新构建 `dist`。

## 验收

1. 营地标题与格子、按钮无重叠，且没有刷新按钮。
2. 选择关卡和关卡确认弹窗完整展示标题、章节、胜利条件及正确禁用样式。
3. 玩家移动仅有一个角色图像，宝箱可见。
4. 击杀怪物后能看到对应掉落提示。
5. 第四层为哥布林哨兵目标。
6. GM 无命运树，重置后重新进入营地为空档案。
