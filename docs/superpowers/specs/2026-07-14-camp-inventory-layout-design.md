# 营地双区背包布局设计

## 目标

将营地的命痕台与装备台改为统一的双区背包界面，取代逐件“上一枚 / 下一枚”的文字选择；角色区全面使用中文显示，并提供清晰的等级经验进度。

## 范围

- 命痕台、装备台、角色区的营地客户端界面与交互。
- 复用现有营地档案、装备管理、命痕装配和追踪请求；不改变玩法数值、掉落、存档字段或云端校验。

## 界面结构

### 命痕台

1. 顶部固定显示收集数、装配数、方案数和命尘。
2. 上半区为“已装配命痕”，显示 8 个固定卡槽；空槽明确标为“空槽”。
3. 下半区为“拥有的命痕”，以可垂直滚动的网格展示持有命痕及其等级。
4. 点击任一命痕卡片打开详情弹窗：
   - 已装配命痕显示“卸下”“追踪”“关闭”。
   - 未装配命痕显示“装配”“追踪”“关闭”。
5. 保留保存方案能力，以单独按钮呈现，不与物品卡片操作混排。

### 装备台

1. 顶部固定显示永久背包容量与金币。
2. 上半区为五个固定已穿戴槽：武器、头盔、护甲、鞋子、饰品。
3. 下半区为可垂直滚动的永久背包网格，沿用现有装备背包的品质、图标与详情表现。
4. 点击装备卡片打开详情弹窗；弹窗集中提供穿戴或卸下、强化、锁定或解锁、出售、关闭操作，并根据装备状态禁用不允许的操作。

### 角色区

1. 职业、技法和状态全部显示中文名称；面向玩家的文本不得暴露英文职业 ID、物品 ID、品质 ID、状态 ID 或技术字段。
2. 唯一允许保留的英文缩写是等级前缀“LV”。
3. 每个职业展示职业名、`LV.<当前等级>`、经验进度条、`当前经验 / 下一级所需经验`、还需经验，以及已解锁技法的中文名称。
4. 原有职业切换按钮保留，未解锁职业明确显示“未解锁”。

## 布局与可读性验收

- 营地面板的标题、分页、摘要、固定上半区、滚动下半区和底部操作区使用明确边界；滚动区不得覆盖或挤压固定区域。
- 卡片网格按可用宽度计算列数与间距；文字使用单行缩放或最多两行换行，不得被裁掉、相互覆盖或压入相邻卡片。
- 详情弹窗的标题、描述、状态和按钮采用固定分区；描述超高时仅内容区滚动，标题和按钮始终可见。
- 在 720 × 1280 的微信竖屏基准下，按钮与文本不重叠，底部“刷新 / 返回大厅”始终可点击；较小安全区域以滚动或缩放容器适配，不能通过遮挡或压缩文字处理。
- 空背包、未装配、未解锁、加载失败等状态均显示中文可理解提示。

## 数据与错误处理

- 仅调用既有 `updateCampConfiguration`、`manageCamp` 与 `startMinghenTracking`；成功后以返回的档案快照刷新界面。
- 使用既有 `_busy` 守卫避免重复提交；失败时保留当前展示并以中文错误提示反馈。
- 命痕或装备状态在请求期间不乐观修改，避免网络失败造成显示与云端配置不一致。

## 验证

1. 手动检查命痕装配、卸下、追踪和保存方案；验证详情弹窗按钮与来源卡片状态一致。
2. 手动检查装备穿戴、卸下、强化、锁定、解锁、出售，以及已穿戴或锁定装备不能出售。
3. 用满 8 个命痕、满 5 个装备槽、长命痕描述、长技法名和满背包数据检查垂直滚动、文字换行及按钮点击区域。
4. 检查营地所有可见文字：除 `LV` 外没有英文 ID 或英文名词。
5. 执行现有 PVE 客户端测试，确保本次纯 UI 改动不影响核心逻辑。
