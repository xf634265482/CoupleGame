# GM 数值文档同步设计

- 日期：2026-06-28
- 项目：`D:\GameSpace\CoupleGame`
- 范围：GM 后台、PVE 数值配置、仓库文档同步

## 1. 目标

为现有 GM 后台增加“一键同步仓库文档”能力。管理员在 GM 页面调整并保存 PVE 数值后，可以继续点击“同步仓库文档”，由系统自动把当前 GM 生效数值回写到仓库内的两份现有文档，无需再手动编辑文档。

目标文档：

- `D:\GameSpace\CoupleGame\specs\260608-pve-destiny-expedition\design.md`
- `D:\GameSpace\CoupleGame\specs\game-design\数值系统V1.md`

## 2. 非目标

以下内容不在本次范围内：

- 不让云函数直接改本机文件
- 不重写整份文档
- 不同步 PVP 文档
- 不修改文档中非数值说明区
- 不把文档内容反向导入数据库

## 3. 设计结论

采用“云端鉴权 + 前端取快照 + 本地定点写文档”的方案。

- GM 前端新增按钮：`同步仓库文档`
- 点击后先调用 `adminTool` 新 action：`syncBalanceDocsPreview`
- 云端只负责：
  - 校验管理员 token
  - 返回当前 PVE 数值完整快照
  - 在同步完成后记录操作日志
- 本地前端负责：
  - 接收数值快照
  - 调用本地同步脚本
  - 定点更新两份 md 文档中的自动同步区块

原因：

- CloudBase 云函数不能安全直接修改本机仓库文件
- 本地页面最接近仓库文件，适合做定点写入
- 云端保留权限校验与日志闭环

## 4. 文档同步策略

### 4.1 同步方式

采用“标记区块同步”。

在两份目标文档中分别加入固定标记：

```md
<!-- GM_SYNC:START:PVE_BALANCE -->
<!-- GM_SYNC:END:PVE_BALANCE -->
```

同步时程序只重写这两个标记之间的内容，标记外内容完全不动。

### 4.2 同步区块内容

自动同步区统一输出以下内容：

- 当前同步时间
- 同步来源说明
- 玩家开局基础数值
- AP 与交互消耗
- 怪物基础倍率
- Boss 基础倍率
- 装备基础倍率
- 遗物运行参数
- 当前已保存的章节覆盖列表
- 当前已保存的单体覆盖列表

### 4.3 不同步内容

以下内容保留人工维护，不做自动覆盖：

- 玩法规则说明
- 掉落机制长文案
- Boss 机制叙述
- 验收条目
- 手写分析、备注、结论

## 5. 数据来源

同步所使用的数据来自 GM 当前已保存的 PVE 数值配置集合：

- 全局默认：`global/default`
- 章节覆盖：`chapter/*`
- 单体覆盖：`unit/*`

需要返回给本地同步器的数据：

- `catalog`
- `configs`
- 按当前规则计算后的全局默认有效值

文档里展示两类信息：

1. 基础生效值
2. 覆盖项清单

这样文档既能体现“当前默认值”，也能明确哪些章节或单体有额外覆盖，避免误解。

## 6. GM 交互设计

### 6.1 新按钮

在 GM 页面顶部按钮区新增：

- `同步仓库文档`

### 6.2 点击流程

1. 前端校验登录状态与 token 有效期
2. 调用 `adminTool.syncBalanceDocsPreview`
3. 云端返回数值快照
4. 前端调用本地同步能力更新两份文档
5. 前端显示结果
6. 前端再调用 `adminTool` 记录同步日志

### 6.3 成功提示

成功时页面显示：

- 已更新文件数量
- 两个文件路径
- 同步时间
- 覆盖摘要

### 6.4 失败提示

失败时要明确区分：

- 云端快照获取失败
- 本地仓库文件不存在
- 文档缺少同步标记
- 本地写入失败
- 日志写入失败

## 7. 云端改动

### 7.1 `adminTool`

新增白名单 action：

- `syncBalanceDocsPreview`
- `syncBalanceDocsLog`

其中：

- `syncBalanceDocsPreview`
  - 校验 token
  - 返回 `catalog`、`configs`、基础有效值
  - 不写文档
- `syncBalanceDocsLog`
  - 记录本次同步目标文件、时间、配置摘要

### 7.2 日志

同步文档属于写操作，必须进入 `admin_logs`。

日志建议包含：

- `action: syncBalanceDocs`
- `payload.files`
- `payload.summary`
- `reason`
- `createdAt`

## 8. 本地同步能力设计

### 8.1 形式

新增本地脚本，例如：

- `scripts/sync-gm-balance-docs.js`

脚本输入：

- 由 GM 页面传入的 balance snapshot JSON

脚本输出：

- 更新结果
- 被改动文件路径
- 是否写入成功

### 8.2 写入规则

脚本负责：

1. 读取目标文档
2. 查找同步标记区
3. 生成新的 markdown 内容
4. 用新内容替换标记区
5. 保存文件

若任一文档缺少标记区，直接失败，不进行部分静默写入。

### 8.3 内容格式

自动同步区采用稳定 markdown 结构，确保反复同步时 diff 可读：

- 二级标题固定
- 表格列顺序固定
- 覆盖清单排序固定
- 时间格式固定

## 9. 安全与边界

- 只有已登录管理员才能触发文档同步
- 云端不接触本机文件
- 本地脚本只允许写死的两份白名单文档
- 不允许前端传任意路径
- 本地同步失败时不应伪造成功日志

## 10. 测试策略

### 10.1 云端

- `syncBalanceDocsPreview` 能返回有效快照
- 非法 token 被拒绝
- action 白名单生效

### 10.2 本地

- 两份文档存在且有标记时可正常更新
- 缺标记时明确失败
- 内容重复同步时结果稳定
- 覆盖列表顺序稳定

### 10.3 端到端

1. 在 GM 改数值并保存
2. 点击同步仓库文档
3. 两份文档自动更新
4. 页面提示成功
5. `admin_logs` 出现同步日志

## 11. 风险与处理

### 风险 1：线上静态站无法直接访问本地仓库

处理：

- 该功能默认服务于本机运行的 GM 页面
- 若用户使用纯线上静态站访问，按钮应直接提示“当前环境不支持本地文档同步”

### 风险 2：文档被人工改动导致标记丢失

处理：

- 同步前先检查标记
- 缺失则阻止写入并提示修复

### 风险 3：文档正文与自动区信息冲突

处理：

- 只把“当前生效数值”维护到自动区
- 保留正文人工说明
- 在自动区中注明“此区由 GM 自动同步，不要手改”

## 12. 实施结果预期

管理员后续日常流程为：

1. 在 GM 页面改数值
2. 点击保存配置
3. 点击同步仓库文档
4. 两份文档自动更新完成

最终效果是：

- GM 数值与仓库文档保持一致
- 不再需要人工补改文档
- 不会误伤原有策划说明
