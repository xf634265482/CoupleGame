# PVE 石块攻击卡顿与表现修复设计

## 问题

`attackRock()` 使用通用 `ATTACK` 事件，但客户端的 `ATTACK` 表现只从怪物列表查找
目标。石块不是怪物，因此命中时没有突进、投射物、受击闪烁和伤害数字。

石块通常需要连续攻击多次。攻击耗尽 AP 后，`_maybeAutoEndTurn()` 会延迟调度自动
结束回合；当前没有保存或取消待执行任务。玩家在延迟窗口内继续输入时，旧任务仍可能
随后执行，造成回合被后台任务抢占，表现为连续攻击期间失去响应或状态跳变。

## 修复设计

### 石块攻击表现

处理 `ATTACK` 时先按 `targetId` 查怪物，未命中再查未消耗的固定实体。目标为
`ROCK` 时复用普通攻击距离规则：近战播放玩家突进，远程播放投射物；接触石块时播放
红色闪烁、轻微震动、命中音效和伤害数字。`ROCK_DESTROYED` 继续使用现有碎裂上飘，
并增加一次短促镜头反馈。

表现失败保持 fire-and-forget，不得阻塞 `_playEvents()` 或改变 core 状态。

### 自动结束回合调度

Controller 只允许存在一个待执行的自动结束回合 timer：

- 调度前若已有任务则不重复调度。
- 玩家主动移动、攻击、交互或手动结束回合时取消旧任务。
- timer 触发时先清空句柄，再次检查 `_busy`、状态和可行动作；条件已变化则放弃。
- 场景销毁时沿现有 managed timer 清理路径取消任务。
- 保留连续自动回合上限，避免玩家被地形完全困住时形成无限循环。

## 验证

- core 回归：连续攻击正确扣除石块 HP/AP，HP 归零后仅产生一次
  `ROCK_DESTROYED`。
- 调度回归：重复请求只产生一个 timer；玩家输入会取消；过期回调不会结束新回合。
- 表现代码确认石块目标进入近战/远程攻击路径，动画 Promise 不进入事件回放等待链。
- 运行 `npm run test:pve`。
- 微信真机连续攻击石块，验证每击有反馈、AP 耗尽只自动结束一次，随后可继续输入。
