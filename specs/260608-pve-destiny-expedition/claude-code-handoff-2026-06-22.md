## 3. 必须修复的三个问题

### 3.1 棋盘不能完全透明

当前完全透明的已探索区让角色像漂浮在天空中。目标不是恢复旧的逐格地砖，而是：

- 在固定战场窗口内部增加一整块连续的半透明战场蒙版。
- 蒙版要让人明确感知这是一块可行走棋盘平面，但仍能看见下方章节背景。
- 格子边缘线必须清楚可见，颜色建议使用低饱和青蓝或章节色；普通状态不可抢过单位和攻击范围提示。
- 选中、移动范围、攻击范围继续拥有更高层级的高亮，不得与普通格线混淆。
- 不能给每一格重新铺独立、明亮、重复纹理的实心地砖。

背景也必须配套调整：

- 每章背景的棋盘中部必须是低细节的地面、平台、遗迹广场或其他落地区域，不能是纯天空或云海。
- 棋盘中部减少建筑、树木、光斑和高对比装饰，避免干扰单位与格线。
- 章节主题元素放在棋盘外缘和远景：第一章空中遗迹、第二章沙海、第三章冰窟、第四章熔岩、第五章星夜命运层。
- 如需重新生成或替换背景，先给用户看预览并确认，不能未经确认直接放入工程。

建议实现边界：

- 棋盘蒙版属于 `FogMapView` 的固定视口内部，层级位于章节背景之上、格线和单位之下。
- 使用一个连续面板/Graphics 层，不要创建 64～100 张高不透明度格子底图。
- 蒙版透明度、颜色允许真机微调，但目标必须是“看得出棋盘平面，同时还能透出背景”。

### 3.2 主战场窗口必须固定

当前真机上，玩家移动到地图顶部和底部时，主战场视觉仍会整体上移或下移。

硬约束：

- `FogMapView` 根节点、战场裁切窗口及其父布局坐标必须固定。
- HUD、怪物卡、战报、玩家状态和底部操作区不得因玩家坐标变化而移动。
- 只允许 `FogMapView` 裁切窗口内部的地图内容层产生镜头位移。
- 不得通过移动 `ExpeditionController` 创建的地图容器、改变锚点、动态修改视口高度或缩放整张棋盘来追踪玩家。
- 章节背景中的棋盘落地区域也要与固定窗口对齐；如果背景需要跟随，只能在同一个 Mask 内同步移动，不能推动页面布局。

排查重点：

- `FogMapView._root` 应是固定尺寸并持有 `Mask`。
- `_content` 才是允许偏移的地图内容层。
- 检查 `refresh()`、`_refreshCamera()`、`setPosition()` 和重新构建地图时，是否有代码间接改变根节点或父节点位置。
- 检查 Cocos 锚点、UITransform 尺寸、父节点 Widget/布局组件是否在内容尺寸变化后重新排版。

验收必须分别截取玩家位于顶部、中部、底部三种状态，并叠图确认：

- 主战场窗口四边坐标不变。
- 顶部和底部信息区坐标不变。
- 镜头偏移只发生在窗口内部。
- 边缘角色与 Boss 不被裁掉。

### 3.3 方向键需要放大和加粗

- 保持 A V4 底部三列结构不变。
- 仅在中间方向键区域内放大四个按键，目标约为当前尺寸的 120%～130%。
- 上下左右箭头需要明显加粗、提高明度和对比度；真机一眼能辨认方向。
- 点击区域不得小于视觉区域，并应保留合理间距，避免误触相邻方向。
- 不得挤压或覆盖左侧返回/角色、右侧攻击/互动/结束回合。
- 不得把方向键改成占满底部的整块十字底盘。

## 4. 不可破坏的布局规则

1. 微信胶囊安全区优先，任何 HUD 不得与胶囊重叠。
2. 顶部怪物卡与资源卡保持约 6:4；无怪物时也保持卡片尺寸，禁止布局跳动。
3. 战报与玩家状态保持约 6:4；不得把战报重新铺满屏幕。
4. 底部保持左/中/右三列，所有按钮不得覆盖任何信息区。
5. 主战场窗口位置和尺寸不跟随角色变化。
6. 字体遵守 18/20/22/24～28 的真机可读性基线，不得为了塞布局再次缩成小字。
7. 视觉继续使用清新 Q 版天空幻想、深海蓝玻璃面板、青色高光、淡金描边；不得改回灰黑写实地牢或厚重 MMORPG 石框。
8. 新 UI/角色/背景素材必须先预览确认，再进入工程。
9. 保留现有资源路径和 `.meta` UUID；替换 PNG 时不要随意删除或重建 `.meta`，避免真机原生加载再次丢图。
