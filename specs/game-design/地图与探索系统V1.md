# 地图与探索系统 V1

> 来源：拆分自 `specs/balance-reference.md` §3/§5/§12 + `assets/scripts/pve/core/{MapGenerator,FloorRules,FogSystem,NeutralEntities,LootSystem}.ts`。
> 实现文件：`MapGenerator.ts`（楼层生成）/ `FloorRules.ts`（通关规则）/ `FogSystem.ts`（迷雾）/ `NeutralEntities.ts`（中性实体交互）/ `LootSystem.ts`（拾取与掉落）。
> 状态：M1 已全部落地，确定性生成与拾取流程均有测试覆盖（AC-6/AC-9/AC-10/AC-13/AC-17/AC-18）。
> 关联文档：[数值系统V1](数值系统V1.md)（怪物/掉落数值表）、[战斗系统V1](战斗系统V1.md)（AP 消耗、怪物 AI）、[Boss设计V1](Boss设计V1.md)（Boss 层规则）、[职业系统V1](职业系统V1.md)（职业碎片）。

## 一、定位

地图与探索系统覆盖「楼层长什么样」「玩家如何看到地图」「如何通关进入下一层」「站在中性格子上能做什么」「打怪/开箱掉落什么」这五件事。整体是 `assets/scripts/pve/core/` 下的纯函数模块：

- `MapGenerator.generateFloor(floor, seed)`：同 `floor + seed` 必然生成相同布局（AC-13 跨端确定性）。
- `FogSystem`：维护 `revealed: boolean[][]` 揭示矩阵，纯函数操作。
- `FloorRules`：钥匙→出口/传送门的通关状态机，均为 `ApplyResult` 纯函数。
- `NeutralEntities` / `LootSystem`：神像、温泉、祭坛、铁匠、宝箱、怪物掉落的 `ApplyResult` 纯函数，部分会级联触发 [灵气强化](数值系统V1.md) 与 [职业进阶](职业系统V1.md)。

## 二、地图生成（MapGenerator）

### 2.1 楼层与地图尺寸

- 全程 5 章 × 每章 5 层 = 25 层（`FLOORS_PER_CHAPTER=5`，`TOTAL_CHAPTERS=5`）。
- `isBossFloor(floor) = floor % 5 === 0`：每章第 5 层为 Boss 层。
- `mapSizeOfFloor(floor)`：Boss 层 10×10（`MAP_SIZE.BOSS`）；第 3 章及以后的普通层 9×9（`MAP_SIZE.HIGH`）；其余普通层 8×8（`MAP_SIZE.NORMAL`）。

### 2.2 生成流程

1. `createRng(seed)` → `rng.shuffle(allCells(size))` 得到全图格子的随机排列 `pool`。
2. `pool.shift()` 作为玩家出生点；以此为中心 `revealAround(radius=FOG_REVEAL_RADIUS=1)` 揭示初始视野。
3. **关键实体放置**：用 `takeFarFrom(pool, from, minSpacing)` 依次从 `pool` 中取出与上一关键点曼哈顿距离 ≥ `minSpacing = max(2, floor(size/2))` 的格子；找不到时退化为取池中距离最远的格子。
   - 钥匙 KEY（距玩家 ≥ spacing）
   - 普通层：出口门 EXIT（距钥匙 ≥ spacing）
   - Boss 层：Boss（距钥匙 ≥ spacing），第 1 章额外在剩余池中放 `CHAPTER1_BOSS_ROCK_COUNT=2` 个 ROCK 地形格（供玩家躲避 AOE）
   - 第 2-5 章 Boss 层各自追加专属地形（详见 [Boss设计V1](Boss设计V1.md) §三~六）：
     - 第 2 章（第 10 层）：`CHAPTER2_SAND_PIT_COUNT=4` 个 SAND_PIT 沙坑，踩入移动 AP +1，也是流沙巨蝎冒出的优先选址。
     - 第 3 章（第 15 层）：`CHAPTER3_ICE_WALL_COUNT=3` 个 ICE_WALL 冰墙（HP=`CHAPTER3_ICE_WALL_HP=10`），阻挡移动，击碎掉 1 灵气。
     - 第 4 章（第 20 层）：LavaLord HP ≤ 50% 进入潮汐阶段后，动态生成 LAVA_TILE 熔岩格（非生成时放置，回合中由 `lavaTideStep` 刷新，详见 Boss设计V1 §五）。
     - 第 5 章（第 25 层）：FateGuardian HP ≤ 33% 时动态生成 `bossId='FATE_MIRROR'` 镜像怪物（非地形，详见 Boss设计V1 §六）。
4. **普通层中性实体**（各 1 个，从 pool 中顺序取格）：CHEST、IDOL（神像）、HOT_SPRING（温泉）、ALTAR（祭坛）；若 `isBlacksmithFloor(floor)`（每章第 3 层、非 Boss 层）再放 1 个 BLACKSMITH。
5. **怪物生成**：
   - 第 1 章按 `generateChapter1Monsters` 的逐层规则表生成（见 §2.3）。
   - 第 2 章及以后：固定 `NORMAL_MONSTER_COUNT=4` 个 NORMAL 怪 + `ELITE_MONSTER_COUNT=1` 个精英怪 + `ANIMA_MONSTER_COUNT=1` 个灵气怪，属性按 [数值系统V1](数值系统V1.md) §三的 `chapterScaling(chapter)` 缩放。
6. **职业碎片**（仅普通层）：`rng.shuffle(ADVANCABLE_CLASSES)` 后取前 `FRAGMENT_COUNT=2` 个职业，各放置 1 个 FRAGMENT 实体，保证同层两个碎片互不同职业（V2 节奏调整，避免单层集中同一职业）。
7. 返回的 `FloorState` 携带 `rngState: rng.state()`——后续楼层内交互（开箱、祭坛、铁匠洗炼等）从此状态续算 RNG，保证确定性。

## 三、楼层通关规则（FloorRules）

### 3.1 普通层流程

1. **拾取钥匙**：玩家移动到 KEY 格时被动触发 `pickKey`（不消耗 AP），标记 `consumed`、`floorState.hasKey=true`，emit `PICK_KEY`。
2. **开启出口门**：玩家站在 EXIT 格 + 已拾取钥匙 + AP ≥ `OPEN_EXIT`(1) + 出口门未开启 → `openExit` 扣 AP、`floorState.status='CLEARED'`，emit `FLOOR_CLEARED`。

### 3.2 Boss 层流程与修复历史

1. 拾取钥匙同普通层。
2. 击败 Boss（`monster.aiState='DEAD'`）后，调用 `spawnPortal`：若 Boss 已死亡 + 持有钥匙 + 尚未生成传送门，则在 Boss 所在格生成 PORTAL 实体，emit `PORTAL_SPAWNED`。**此步骤不会让楼层进入 CLEARED**。
3. 玩家走到 PORTAL 格 + AP ≥ `OPEN_EXIT`(1) → `interactPortal` 扣 AP、`status='CLEARED'`，emit `FLOOR_CLEARED`。

> **修复历史**：M1 最初将"传送门生成"与"楼层结算"合并为一步（生成传送门即 `FLOOR_CLEARED`），但玩家反馈打完 Boss 后无法继续探索遗漏的宝箱/神像/温泉。因此拆分为 `spawnPortal`（仅浮现传送门）与 `interactPortal`（玩家主动走入才结算）两步，给予玩家自由探索窗口。

### 3.3 楼层状态判定

`isFloorCleared(floorState) = floorState.status === 'CLEARED'`，由 `ExpeditionState.advanceFloor` 据此决定是否可以推进到下一层（详见 [战斗系统V1](战斗系统V1.md) §八 回合编排）。

## 四、迷雾系统（FogSystem）

- `createFogGrid(size)`：生成全 `false` 的 `size×size` 揭示矩阵 `revealed[y][x]`。
- `revealAround(revealed, center, radius=FOG_REVEAL_RADIUS)`：以 `center` 为中心按**曼哈顿距离** `radius` 原地揭示格子，返回本次新揭示的坐标列表（已揭示格子不重复返回，幂等）。`FOG_REVEAL_RADIUS=1`，即每次只揭示十字+对角共 5 格（曼哈顿距离≤1）。
- `reveal(revealed, center, radius)`：不可变版本，深拷贝矩阵后调用 `revealAround`，供 `MovementSystem.applyMove` 等需要保持状态不可变的调用方使用。
- `isRevealed(revealed, pos)`：边界检查 + 查表。

地图生成时会以玩家出生点为中心做一次初始揭示；此后每次移动调用 `reveal`/`revealAround` 增量揭示（移动逻辑与 RARE+ 靴子的额外揭示半径词条详见 [战斗系统V1](战斗系统V1.md) §三）。

此外，迷雾中的怪物主动攻击玩家时，`monsterAttack` 会以 `radius=0` 单独揭示该怪物所在格（不揭示其周围），让玩家知道是谁打的（详见 [战斗系统V1](战斗系统V1.md) §4.3）。

## 五、中性实体交互（NeutralEntities）

四类中性实体均要求「玩家站在实体格 + AP 足够 + 实体未消耗」，否则 no-op（不扣 AP、不产生事件）。

| 实体 | AP 消耗 | 效果 | 事件 |
|------|------|------|------|
| IDOL 神像 | `USE_IDOL`=1 | 永久 `maxHp += IDOL_MAX_HP_BONUS(1)`，当前 `hp` 同步 +1（避免出现"20/21"的视觉怪状态） | `IDOL_BLESSING` |
| HOT_SPRING 温泉 | `USE_HOT_SPRING`=1 | 恢复 `maxHp × HOT_SPRING_HEAL_RATIO`(0.4=40% maxHp) HP，超出上限截断；HP 已满则 no-op（避免浪费 AP） | `HOT_SPRING_HEAL` |
| ALTAR 祭坛 | `USE_ALTAR`=1 | 随机获得 `[ALTAR_ANIMA_MIN, ALTAR_ANIMA_MAX]` = `[20, 35]` 灵气，经 `addAnima` 计入进度，可能连锁触发 [灵气强化](数值系统V1.md) §八 | `ALTAR_USED` + 可能的 `ANIMA_STRENGTHEN` |
| BLACKSMITH 铁匠 | 不消耗 AP | 见下 §5.1 强化/洗炼 | `BLACKSMITH_UPGRADE` / `BLACKSMITH_REROLL` |

三个消耗 AP 的实体（神像/温泉/祭坛）使用后会标记 `consumed=true`，铁匠不消耗、可重复交互（多次强化不同槽位）。

### 5.1 铁匠服务

- **强化 `upgradeEquip(state, entityId, slot)`**：指定槽位装备 `baseStat += 1`，消耗 `BLACKSMITH_UPGRADE_COST=20` 金币；命运树 C3「巧匠人脉」可享 `blacksmithDiscount` 折扣（费用下限为 1）。不消耗 AP，不消耗实体。
- **洗炼 `rerollEquipTrait(state, entityId, slot)`**：从 `EQUIP_TRAIT_POOL` 中随机替换该槽位装备的词条，消耗 `BLACKSMITH_REROLL_COST=30` 金币。**仅 EPIC/LEGENDARY 品质装备有词条槽**（`REROLL_QUALITY_MIN`），低品质装备词条栏留空，洗炼为 no-op。

## 六、拾取与掉落流程（LootSystem）

### 6.1 宝箱 `openChest`

玩家站在 CHEST 格 + AP ≥ `OPEN_CHEST`(1) + 未开启 → 扣 AP、标记 `consumed`、推进楼层 RNG，结算掉落：

1. `rollNormalMonsterDrop(rng)`：50% 仅金币 / 25% 仅灵气 / 25% 金币+灵气（基础掉落范围 `goldSmall=[5,12]`、`animaSmall=[10,25]`）。
2. 额外独立判定 10% 概率掉落 COMMON 品质装备（随机槽位）。
3. 命运树 C2「宝箱老手」：金币按 `chestGoldBonusPct` 加成后取整。
4. emit 顺序：`OPEN_CHEST` → `LOOT`（携带 gold/anima/equip）→ 若灵气达阈值，追加 `ANIMA_STRENGTHEN`。

> M1 简化：未单列宝箱专属掉落表，复用 `NORMAL_MONSTER_DROP`（详见 design.md AC-6）。

### 6.2 击杀掉落 `applyMonsterKillDrop`

调用方需保证在 `KILL` 事件 emit 之后调用（顺序：`ATTACK → KILL → applyMonsterKillDrop`），按怪物 `type` 派发：

| 怪物类型 | 掉落规则 |
|------|------|
| NORMAL | `rollNormalMonsterDrop`：同宝箱基础掉落（50/25/25），额外 3% (`EQUIP_CHANCE`) 独立掉落 COMMON 装备 |
| ANIMA | `rollAnimaMonsterDrop`：100% 掉落 `animaLarge=[40,60]` 大量灵气（AC-18） |
| ELITE | `rollEliteMonsterDrop`：40% 中量金币 / 30% 金币+灵气 / 15% 高额金币 / 10% 掉落 FINE 品质随机槽位装备（AC-17）/ 5% 掉落「职业碎片对」——`rng.shuffle(ADVANCABLE_CLASSES)` 取前两个不同职业各 +1 碎片 |
| BOSS（哥布林酋长） | `applyGoblinChiefDrop`：50% 概率必掉「哥布林酋长的战斧」（直接装入 WEAPON 槽，覆盖原武器）+ 一份 `rollNormalMonsterDrop` 普通掉落作为通关奖励 |
| BOSS（2-5章通用） | `rollGenericBossDrop`：固定 10 金 + 按章节品质表掉落 1 件随机槽位装备（章节 2→FINE，3→RARE，4→EPIC，5→LEGENDARY） |

### 6.3 通用结算逻辑 `applySimpleDrop`

所有非宝箱掉落统一走该内部函数，避免重复逻辑：

- **金币**：命运树/职业词条 `strengthen_gold_find` 时 ×1.2 取整。
- **灵气**：经 `addAnima` 计入进度，可能级联 `ANIMA_STRENGTHEN`。
- **装备**：直接替换玩家对应槽位装备（无需返回背包，M1 装备即穿即换，详见 [职业系统V1](职业系统V1.md)）。
- **职业碎片对**：累加到 `player.classFragments`；若任一非当前职业的碎片数 ≥ `CLASS_FRAGMENTS_TO_ADVANCE`(5)，追加 `CLASS_CAN_ADVANCE` 事件提示玩家可进阶。

emit 事件统一为单条 `LOOT`（携带 `gold`/`anima`/`equip`/`fragmentPair`/`source`），后续可能追加 `ANIMA_STRENGTHEN` / `CLASS_CAN_ADVANCE`。

## 七、已知限制

1. 宝箱未单列专属掉落表，复用普通怪掉落表（M1 简化，design.md AC-6 已确认）。
2. 中性实体（神像/温泉/祭坛/宝箱/铁匠/碎片）每普通层各固定数量（均为 1，碎片为 2），未随章节难度变化。
3. `generateChapter1Monsters` 中的 `floorNum` 参数当前未使用（保留供未来扩展）。
