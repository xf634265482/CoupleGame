# 职业系统 V1

> 来源：拆分自 `specs/balance-reference.md` §6-7 + `assets/scripts/pve/core/ClassSystem.ts`。
> 实现文件：`ClassSystem.ts`（碎片拾取 / 进阶逻辑）/ `PveConstants.ts`（`CLASS_STATS`）/ `CombatSystem.ts` & `MonsterAI.ts`（词条内联实现）。
> 状态：已实现（design §8 AC-15，M2 范围内核心逻辑完成）；**V2 节奏调整已实现**（见 §二）。

## 一、定位

职业系统是**单局内（run 内）的进阶成长**：玩家初始为冒险者，通过拾取「职业碎片」积累到阈值后可进阶为狂战士 / 射手 / 隐匿者三者之一。进阶后获得对应的属性加成与专属词条。

## 二、碎片与进阶流程（V2 节奏调整）

> **设计目标**：让"第一章Boss前觉醒"成为少数运气玩家的特殊体验，大部分玩家会停在"差一个碎片"的状态，从而对后续楼层产生"追逐"欲望。

- 进阶所需同职业碎片数：**5**（`CLASS_FRAGMENTS_TO_ADVANCE`，原为3）。
- 每个普通层随机生成 **2** 个碎片（`FRAGMENT_COUNT`），且**同一层的2个碎片职业互不相同**（`MapGenerator.ts` 用 `rng.shuffle(ADVANCABLE_CLASSES)` 取前2个，防止单层集中同一职业）。
- 流程（`pickFragment` → `CLASS_CAN_ADVANCE` 事件 → Controller 弹 UI → `applyClassAdvance`），与 `AnimaSystem` 的 `ANIMA_STRENGTHEN` 流程结构对称：
  1. `pickFragment(state, entityId)`：玩家位置匹配且未消耗的碎片实体 → 标记 consumed，对应职业 `classFragments[classId] += 1`，emit `FRAGMENT_PICKED`。
  2. 若任一**非当前职业**的碎片数 ≥ 5，emit `CLASS_CAN_ADVANCE`（携带可进阶职业列表）。
  3. `applyClassAdvance(state, classId)`：
     - 校验该职业碎片数 ≥ 5 且非当前职业。
     - 消耗该职业碎片数 - 5（多出部分保留）。
     - 切换 `classId`。
     - 立即应用职业进阶 HP 代价。
     - emit `CLASS_ADVANCED`。

### 第一章Boss前节奏推演

第一章共5层（第3层铁匠、第5层Boss），Boss前有3个普通层（第1/2/4层）×2碎片=6个碎片。在"同层不重复职业"规则下，每层相当于"随机跳过1个职业，另外2个各+1"，3层后单职业碎片数**理论上限为3**（裸随机永远到不了5）：

- 22.2% 玩家：三个职业都停在 2/5
- 66.7% 玩家：恰好一个职业停在 3/5（主力人群，"差两个"）
- 11.1% 玩家：两个职业同时停在 3/5

要在Boss前觉醒（达到5），必须叠加"幸运加成"：
- **命运树B3「职业先驱」**（开局给随机可进阶职业 +1 碎片）：解锁B3的玩家中，约 **29.6%** 能让某职业碎片数达到4，但仍差1（5-4=1），需再叠加一次精英碎片对掉落才能觉醒。
- **精英怪5%概率掉落"职业碎片对"**（见§六）：给2个不同职业各+1，可能恰好补到该职业差的最后1个。

整体效果：第一章Boss前能觉醒的玩家是**叠加了B3 + 精英碎片对双重幸运**的极少数；绝大多数玩家会带着"某职业3/5或4/5"的状态进入后续章节，形成持续的追逐感。

## 三、职业属性

| 职业 | 攻击加成 | 攻击范围加成 | 移动加成 | 进阶 HP 代价 | 变量 |
|------|----------|------------|----------|------------|------|
| 冒险者（初始） | +0 | +0 | +0 | 0 | `CLASS_STATS.ADVENTURER` |
| 狂战士 | **+15**（×10基准，原+1.5） | +0 | +0 | **max(30, 当前HP÷2下取整)，保底剩 1 血**（×10基准，原最少扣3） | `ClassSystem.applyClassAdvance` |
| 射手 | +5（×10基准，原+0.5） | **+2** | +0 | 0 | `CLASS_STATS.ARCHER` |
| 隐匿者 | +10（×10基准，原+1） | +0 | **+1 格/AP** | 0 | `CLASS_STATS.ROGUE` |

> 攻击力 = `BASE_ATTACK(10)` + 职业攻击加成 + 武器 baseStat + 词条加成
> 实际伤害 = `Math.max(10, Math.round(rawAttack))`（×10基准，原 `Math.max(1, ...)`）

**狂战士进阶代价说明**：扣除当前 HP 的一半（向下取整），但至少扣 30 点（×10基准，原3），防止玩家故意以低血量进阶来规避代价；扣除后保底剩 1 HP（不会因进阶直接死亡）。

## 五、与其他系统的接口

- **命运树 B3「职业先驱」**：远征开局随机为一个可进阶职业（狂战士/射手/隐匿者）增加 `fragmentBonus` 个碎片（`applyFragmentBonus`，命运树未解锁 B3 时 no-op）。
- **命运树 E3「命运护佑」**：从当前职业的强化词条池（`strengthenPoolForClass`）中三选一，直接加入 `classTraits`。
- **灵气强化（AnimaSystem）**：强化词条池 `strengthenPoolForClass(classId)` 按当前职业返回可选词条池，是词条获取的主要来源（除 E3 外）。

## 六、精英怪掉落：职业碎片对（V2，替代原「进阶卡」）

- `ELITE_MONSTER_DROP.FRAGMENT_PAIR`：**5%** 概率（原 `ADVANCE_CARD`，原效果是直接补满某随机职业碎片至阈值）。
- 新效果：随机选取 **2 个不同职业**（`rng.shuffle(ADVANCABLE_CLASSES)` 取前2个），各 **+1** 碎片。
- 设计意图：原"进阶卡直接补满"在阈值提升到5后过于强力（一次掉落即可决定觉醒），改为"+1/+1"后更像一次小幅推进，玩家仍需自己攒够大部分碎片，但能作为"压哨补足最后1个"的关键变量（见§二节奏推演）。
- 实现：`LootSystem.ts` 的 `rollEliteMonsterDrop` 返回 `{ fragmentPair: [classA, classB] }`，`applyMonsterKillDrop` 中各 `classFragments[cls] += 1` 并检测 `CLASS_CAN_ADVANCE`。

## 七、二阶进阶/觉醒（已实现）

> 实现文件：`PveConstants.ts`（常量/`AWAKEN_FORMS`）、`ClassSystem.ts`（`getAwakenEligible` / `applyClassAwaken`）、`CombatSystem.ts` & `MovementSystem.ts`（6 个觉醒词条内联实现）、`ExpeditionState.ts`（`maxChapterCleared` 记录 / `applyDeath` 重置）、`ExpeditionController.ts` + `PveToastView.ts`（觉醒确认弹窗）、`PveCharacterPanel.ts`（觉醒状态展示）。

### 觉醒条件

进阶后，该职业碎片会继续累积，达成以下**全部**条件时触发二阶觉醒：

1. **本职业碎片数 ≥ 10**（`CLASS_FRAGMENTS_TO_AWAKEN`，远高于一阶进阶阈值 5，对应"差一点"后的长线追逐）。
2. **另外两个职业碎片合计 ≥ 7**（`AWAKEN_SECONDARY_TOTAL`，取奇数保证两者必有高低，用于决定觉醒形态）。
3. **已击败第三章 Boss（冰霜巨人）**（`AWAKEN_REQUIRED_CHAPTER = 3`）：通关章节 Boss 层时记录 `player.maxChapterCleared`，作为本条件的判定依据。
4. 一局内最多觉醒一次（已设置 `awakenForm` 后不再满足）。

满足条件时（拾取碎片或通关Boss层后检测），emit `CLASS_CAN_AWAKEN` → Controller 弹出确认 UI（`showClassAwakenChoice`，可选择「立即觉醒」或「稍后决定」）→ 确认后调用 `applyClassAwaken`：
- 消耗本职业碎片 `CLASS_FRAGMENTS_TO_AWAKEN`（10）个（多余保留）。
- 写入 `player.awakenForm`，并将该形态的「轻量属性词条」+「觉醒专属词条」加入 `classTraits`。
- emit `CLASS_AWAKENED`。

### 觉醒形态判定

每个主职业有 2 种觉醒形态，由 `AWAKEN_SECONDARY_ORDER` 中固定的 [副职业A, 副职业B] 碎片数对比决定：副职业A碎片数 > 副职业B → 形态_1，否则 → 形态_2。

| 主职业 | 副职业A / 副职业B | 主题映射 |
|--------|-------------------|----------|
| 狂战士 | 射手 / 隐匿者 | 范围（_1）/ 机动（_2） |
| 射手 | 狂战士 / 隐匿者 | 输出（_1）/ 机动（_2） |
| 隐匿者 | 狂战士 / 射手 | 输出（_1）/ 范围（_2） |

### 6 种觉醒形态（"B+轻量A组合"）

每个形态 = 复用现有通用词条的轻量属性加成（A） + 1 个全新的觉醒专属词条（B）。所有形态名称与词条均为中文展示，无英文标识暴露给玩家。

| 形态（内部 id） | 名称 | 轻量属性（A，复用通用词条） | 觉醒词条（B） | 效果 |
|------------------|------|---------------------------|---------------|------|
| 狂战士·破阵型（`BERSERKER_1`） | 狂战士·破阵型 | 鹰眼（攻击范围 +1） | 横扫 | 攻击命中后，对目标周围相邻怪物造成 50% 溅射伤害 |
| 狂战士·嗜杀型（`BERSERKER_2`） | 狂战士·嗜杀型 | 疾步（移动消耗 -1 AP） | 狂热 | 击杀目标后，下一次攻击必定暴击（×3）并额外回复 20 点 HP（×10基准，原2） |
| 射手·强击型（`ARCHER_1`） | 射手·强击型 | 强化攻击（攻击 +5，×10基准，原+0.5） | 强弓 | 基础伤害额外提升 15 点（×10基准，原1.5） |
| 射手·游击型（`ARCHER_2`） | 射手·游击型 | 疾步（移动消耗 -1 AP） | 连珠 | 连射概率提升至 60%，且连射命中后有 30% 概率触发连锁射击 |
| 隐匿者·屠戮型（`ROGUE_1`） | 隐匿者·屠戮型 | 强化攻击（攻击 +5，×10基准，原+0.5） | 处决 | 目标 HP ≤ 30% 时直接处决；背刺伤害提升至 3 倍 |
| 隐匿者·影袭型（`ROGUE_2`） | 隐匿者·影袭型 | 鹰眼（攻击范围 +1） | 影袭 | 每回合可触发 2 次背刺伤害 |

**实现细节补充**：
- 「狂热」（内部 id `awakened_frenzy`）使用 `floorState.frenzyPending` 标记：击杀后置 true，下次攻击消耗（伤害 ×3 + 回复 20 HP，×10基准，原2）后置 false。
- 「影袭」（内部 id `awakened_shadow_strike`）复用 `backstabAvailable` 标记（移动后置 true），并新增 `floorState.shadowStrikeCount`（每回合上限 2 次，`endTurn` 时重置为 0）。
- 「处决」（内部 id `awakened_execute`）：背刺触发时伤害倍率从 ×2 提升为 ×3；额外校验目标 `hp / maxHp ≤ 0.3` 时直接将伤害设为 `monster.hp`（必杀）。
- 「连珠」（内部 id `awakened_volley`）：将射手的「连射」（30%）替换为 60% 概率触发追加射击，命中后再有 30% 概率对范围内另一存活目标触发连锁伤害（同基础伤害，不含词条加乘）。
- 「横扫」（内部 id `awakened_cleave`）：溅射伤害 = `Math.max(10, Math.round(主伤害 × 0.5))`（×10基准，原 `Math.max(1, ...)`），对主目标曼哈顿距离 = 1 的所有存活相邻怪物各造成一次。
- 角色面板（`PveCharacterPanel`）：已觉醒后职业碎片栏显示「（已觉醒）」，未觉醒时显示 `当前/10（觉醒）` 进度。
