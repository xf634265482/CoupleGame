# 命运树设计 V1

> 来源：拆分自 `specs/balance-reference.md` §12 + `assets/scripts/pve/core/DestinyTreeSystem.ts` + `specs/260610-destiny-tree-ui/design.md`。
> 实现文件：`DestinyTreeSystem.ts`（核心逻辑）/ `PveConstants.ts`（数值与节点定义）/ `DestinyTreeView.ts` + `DestinyTreeController.ts`（UI）。
> 状态：核心逻辑 + 服务端校验 + UI 已全部落地（M1）。

## 一、定位

「命运碎片成长树」是**账户级、局外（meta）永久成长系统**，与单局内的「灵气强化」「装备」「职业进阶」相互独立、互不覆盖：

- 货币：`destinyShards`（命运碎片，账户级，存储于 `users.destinyShards`）。
- 解锁记录：`unlockedTreeNodes: string[]`（账户级，存储于 `users.unlockedTreeNodes`）。
- 生效时机：所有已解锁节点的效果在 `startExpedition()` 时一次性汇总为 `RunPlayer.treeBonuses` 快照（`getTreeBonuses()`），随存档持久化——单局内不会因为账户树变化而中途改变。

## 二、结构

5 列 × 3 节点（共 15 节点），列代表方向、行代表深度：

| 列 | 主题 |
|----|------|
| A | 生存 |
| B | 战斗 |
| C | 财富 |
| D | 强化 |
| E | 天命 |

**解锁规则**：
- 每列内节点须按 `order` 1→2→3 顺序解锁（解锁 A2 前必须先解锁 A1）。
- 解锁消耗 `destinyShards`，扣除后不可逆。
- 服务端权威重新校验：节点存在 / 未重复解锁 / 碎片足够 / 同列顺序满足，四项任一不满足则拒绝（`canUnlockNode`）。

## 四、E2/E3「三选一」机制

与已有的 `ANIMA_STRENGTHEN`（灵气强化）三选一模式一致：

1. `startExpedition()` 时调用 `buildPendingTreeChoices()`，按 `treeBonuses.hasEquipChoice` / `hasTraitChoice` 依次（先 E2 后 E3）生成 `pendingTreeChoices` 队列。
2. RNG 通过 `deriveTreeRng(runSeed)` 派生（与楼层种子隔离，保证 AC-13 跨端复算确定性）。
3. 玩家通过 `resolveTreeChoice(state, index)` 逐个选定：
   - **EQUIP（E2）**：选中的装备直接装入对应槽位，覆盖原装备（原装备视为出售/丢弃，M1 不返还金币）。
   - **TRAIT（E3）**：选中的词条加入 `classTraits`（重复词条去重 no-op）。

## 五、UI / 入口（specs/260610-destiny-tree-ui）

- 入口：大厅菜单新增「命运树」按钮 → 独立场景 `destiny_tree.scene`。
- 展示：`DestinyTreeView` 渲染 5 列 × 3 节点网格，三态着色（已解锁 / 可解锁 / 锁定），每个节点格内常驻显示节点名称、效果简述（`DestinyTreeNodeDef.desc`）与解锁所需碎片（已解锁节点不再显示碎片消耗）。
- 解锁：点击可解锁节点 → 调用云函数 action `unlockTreeNode`（服务端用 `PveDestinyTree.js` 镜像逻辑重新校验顺序/碎片/重复解锁后原子扣费写入）。

## 六、已知范围限制 / 待规划

- E2/E3 的「三选一」展示 UI 在命运树面板中**不展示**，仅在远征开局时通过既有 `PendingTreeChoice` 弹窗流程呈现。
- 节点数值已随 M1「全局 ×10 数值基准」重构同步更新（详见 `数值系统V1.md`），后续如调整需同步更新本文件、`PveConstants.ts` 中的数值常量与 `DESTINY_TREE_NODES[].desc` 文案。
- 命运碎片（`destinyShards`）的获取来源（远征结算掉落比例等）在本设计文档范围之外，参见数值系统设计中的奖励结算部分。
