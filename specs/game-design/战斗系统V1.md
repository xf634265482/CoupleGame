## 一、定位

本文档覆盖远征"单层探索"内的核心循环系统：移动、攻击、AP 资源、怪物 AI、状态效果（Buff/DOT）、二阶觉醒技能、战报展示与回放节奏，以及确定性/性能相关的实现约束。所有逻辑均为**纯函数**（零 `cc` 依赖），输入 `ExpeditionState` 输出 `ApplyResult`（新状态 + 事件列表），保证客户端模拟与云端复算结果一致（AC-13）。

## 二、AP 行动点系统（ApSystem）

- 每回合 AP 上限 = `AP_BASE(8) + dice`，`dice ∈ [1,6]`（`rollAp`），即 AP ∈ [9,14]。
- 行动固定消耗（`AP_COST`）：

  | 行动 | 消耗 | 说明 |
  |------|------|------|
  | `MOVE` | 2 | 移动 1 格（词条/装备可减免，见§三） |
  | `ATTACK` | 3 | 普通攻击（刻意调高，限制每回合攻击次数，强化资源决策） |
  | `OPEN_CHEST` / `OPEN_EXIT` / `USE_IDOL` / `USE_HOT_SPRING` / `USE_ALTAR` | 各 1 | 中立实体交互（铁匠铺不耗 AP，只收金币） |

- `canAfford(ap, action)` / `spend(ap, action)`：校验与扣减；`spend` 在 AP 不足时抛错，调用方必须先 `canAfford`。
- `isExhausted(ap)`：AP 低于所有行动中的最小消耗时返回真（用于"无法再行动，应结束回合"的提示判断）。
- 命运树 B2「急行军」（`treeBonuses.apDiceBonus`）与 ADVENTURER 通用词条 `strengthen_ap_up`（各 +1 AP 上限）在 `startFloorTurn`/`endTurn` 中叠加生效。

## 三、移动系统（MovementSystem）

- `applyMove(state, dir)`：四方向（UP/DOWN/LEFT/RIGHT）单格移动，纯函数、no-op 不消耗 AP。
- **拒绝条件**（任一满足则原样返回 state，不产生事件）：目标格越界 / AP 不足 / 目标格被存活怪物占据 / 目标格被未消耗的 `ROCK` 实体阻挡。
- **移动消耗计算**（`cost`）：
  1. 基础消耗：ROGUE `swift` 词条 → 1 AP；否则 `AP_COST.MOVE`（2）。
  2. 减速惩罚：`playerMoveApPenaltyRounds > 0`（冰霜哥布林命中等）时 +1 AP。
  3. 鞋子减免：`SHOES.baseStat` 直接抵扣（`shoesReduction`），最终 `cost = max(1, base + slowPenalty - shoesReduction)`（最低 1 AP）。
  4. **RARE+ 鞋子首步免费**：`baseStat ≥ SHOES_FIRST_MOVE_THRESHOLD` 且本回合未用过 → 本次移动 0 AP（`shoesFirstMoveDone` 标记，每回合开始重置）。
- **迷雾揭示**：移动成功后以 `FOG_REVEAL_RADIUS(1)` 为半径揭示新格；`SHOES.baseStat ≥ SHOES_REVEAL_BONUS_THRESHOLD`（FINE+）时半径 +1。新揭示格通过 `REVEAL` 事件下发。
- **移动副作用**：
  - ROGUE `backstab` / 二阶觉醒 `awakened_shadow_strike` → 移动后 `floorState.backstabAvailable = true`，下次攻击触发双倍/三倍伤害（见§四）。

## 四、攻击系统（CombatSystem）

### 4.1 玩家攻击力/范围（playerAttackPower）

```
rawAttack = BASE_ATTACK(10) + 职业攻击加成 + 武器baseStat
          + (marksman ? +5 : 0)            // ARCHER 射手精通（×10基准，原+0.5）
          + (strengthen_attack_up ? +5 : 0) // ADVENTURER 通用强化（×10基准，原+0.5）
          + (awakened_power_shot ? +15 : 0) // 觉醒·强弓（×10基准，原+1.5）
          + treeBonuses.attackBonus          // 命运树 B1 武者直觉
range = BASE_ATTACK_RANGE + 职业攻击范围加成 + (eagle_eye ? +1 : 0)
damage = max(10, round(rawAttack))   // ×10基准，原 max(1, ...)
```

### 4.1.1 攻击目标选择与提示

- 点击格子可直接指定攻击目标（范围内任意存活怪物）。
- "攻击"按钮（`_onAttack`）自动选择目标：先过滤出**攻击范围内**（曼哈顿距离 ≤ `playerAttackPower(player).range`）的存活怪物，再按曼哈顿距离从近到远排序，取最近一只；多只等距时取 `floorState.monsters` 数组中靠前者（与生成顺序相关，非随机）。范围外没有目标时视为"无可攻击目标"。
- **目标提示**（`FogMapView.showAttackTarget`）：每次 `_refreshAll` 时，在"攻击"按钮当前会命中的目标格上绘制一圈细描边（淡黄色），不遮挡格内图标；无可攻击目标时清除。提示随玩家/怪物移动实时更新，帮助玩家预判攻击按钮的命中对象，且为静态描边、不产生 toast，避免打扰。
  - **修复历史**：M1 最初 `_currentAttackTarget` 仅按"全图最近的存活怪物"选取，未校验是否在攻击范围内。当最近的怪物位于攻击范围外（甚至未揭示的迷雾格）时，会在迷雾区域画出一个空的高亮描边，既造成视觉上"莫名出现的框"，也间接暴露了未探索区域存在怪物的信息。修复后仅范围内目标才会被选中和高亮，与"攻击"按钮的真实命中结果保持一致。

### 4.2 玩家攻击结算流程（playerAttack）

1. **前置校验**（不满足则 no-op）：目标存活、AP 足够、目标在攻击范围内（曼哈顿距离）、目标未处于"潜地"状态（沙虫女王专属）。
2. **Boss 闪避（内联）**：目标为 `FATE_GUARDIAN` 且玩家 HP ≤ `FATE_GUARDIAN_HP_THRESHOLD`(50%) 时，`FATE_GUARDIAN_DODGE_CHANCE`(40%) 概率完全闪避——仍消耗 AP 并推进 RNG，但无伤害事件。
3. **确定性伤害加成**（按顺序叠加，不消耗 RNG）：
   - `berserk`（HP≤50%）：+10（×10基准，原+1）
   - `backstab` / `awakened_shadow_strike`（移动后首次攻击，`backstabAvailable`）：×2（`awakened_execute` 下提升至 ×3）
   - `assassin_heart`（目标非 CHASE）：+20（×10基准，原+2）
   - `awakened_frenzy` 待触发标记（`frenzyPending`）：×3
4. **概率词条**（消耗 `rngState`，即使未命中也推进，保证确定性）：
   - `crit`（ARCHER 暴击）：20% ×3
   - `awakened_execute`：目标 HP/maxHp ≤ 30% 时直接处决（`damage = max(damage, monster.hp)`）
5. **结算与连锁效果**：
   - 主目标伤害结算（`resolveHit`），致死则 `KILL` 事件 + 掉落结算。
   - `awakened_cleave`（觉醒·横扫）：对主目标相邻（曼哈顿距离=1）的存活怪各造成 50% 溅射伤害。
   - `multi_shot`（30%）/ `awakened_volley`（60%，连射命中后 30% 概率连锁另一存活目标）：基础伤害（不叠加词条加成）。
6. **玩家自身回血**：`life_steal`（每次攻击 +10HP，×10基准，原+1）、`blood_rage`（击杀 +20HP，×10基准，原+2）、`awakened_frenzy` 触发（+20HP，×10基准，原+2），均 `min(maxHp, ...)`。

### 4.3 怪物攻击玩家（monsterAttack）

- 校验：目标存活、距离 ≤ 怪物攻击范围（不消耗玩家 AP，由 `MonsterAI` 在怪物回合驱动）。
- **揭示攻击者位置**：通过校验后，若攻击者所在格尚未揭示，立即 `reveal(revealed, monster.pos, radius=0)` 仅揭示该单格并 emit `REVEAL` 事件（顺序在伤害事件之前）——避免"被迷雾里的怪物打了一下却看不到是谁打的"。该揭示与是否命中/闪避无关，即使 `afterimage` 触发完全闪避也会揭示攻击者。不会连带揭示攻击者周围其他格子。
- `afterimage`（ROGUE 残影）：本层首次受击 100% 闪避（`hasAfterimage`，触发后置 false）。
- **装备减伤**：`max(0, rawDamage - ARMOR.baseStat)`，再乘以可选 `damageMult`（Boss 双倍伤害机制），最终 `max(10, round(...))`（保底受 10 伤害，×10基准，原 `max(1, ...)`）。
- `undying`（BERSERKER 不屈）：本层首次将死时保留 1 HP（`undyingAvailable`，一次性）。
- `counter`（BERSERKER 反击）：未死亡时对攻击者造成 10 伤害（`max(10, hp-10)`，×10基准，原1，不触发击杀）。
- **第一章变体怪命中效果**（叠加制）：
  - 冰霜哥布林（`VARIANT_FROST_GOBLIN`）：`playerMoveApPenaltyRounds += FROST_MOVE_PENALTY_ROUNDS(2)`（移动+1AP，持续2回合）。
  - 赤炎哥布林（`VARIANT_FIRE_GOBLIN`）：`playerFireBurnRounds += FIRE_BURN_ROUNDS(2)`（灼烧，按 5/回合累计，×10基准，原0.5HP，累计达10的倍数时触发10点伤害）。

## 五、词条一览（CombatSystem 内联实现）

一阶职业词条详见 [职业系统V1 §四](职业系统V1.md#四职业词条效果)。本节补充**二阶觉醒**专属词条（V2 新增，`ClassSystem.applyClassAwaken`）：

### 5.1 二阶觉醒触发条件（getAwakenEligible）

- 当前职业为已进阶职业（BERSERKER/ARCHER/ROGUE）且尚未觉醒（`!player.awakenForm`）。
- 本职业碎片数 ≥ `CLASS_FRAGMENTS_TO_AWAKEN`(10)。
- 另外两个职业碎片数合计 ≥ `AWAKEN_SECONDARY_TOTAL`(7，奇数保证两者必有高低，决定觉醒形态)。
- 已击败第三章 Boss（`player.maxChapterCleared ≥ AWAKEN_REQUIRED_CHAPTER`(3)）。
- 满足条件时在 `applyClassAdvance`/`advanceFloor` 中 emit `CLASS_CAN_AWAKEN`。

> **注**：[职业系统V1 §七](职业系统V1.md#七待规划--已知缺口) 中"二阶进阶/觉醒机制（讨论中，待定方案）"已在代码中落地为本节描述的 `applyClassAwaken`，该文档待同步更新。

### 5.2 觉醒形态（applyClassAwaken）

- 形态判定：副职业（另外两个职业）碎片数较多者对应"形态一"，否则"形态二"（`AWAKEN_SECONDARY_ORDER`）。
- 消耗本职业碎片 `CLASS_FRAGMENTS_TO_AWAKEN`(10) 个（多出部分保留），不改变 `classId`，写入 `awakenForm`，并将"轻量属性词条(A)"+"专属觉醒词条(B)"加入 `classTraits`。

| 形态 | 名称 | 轻量词条(A) | 专属词条(B) | 效果 |
|------|------|-------------|-------------|------|
| BERSERKER_1 | 狂战士·破阵型 | `eagle_eye`（攻击范围+1） | `awakened_cleave`（横扫） | 攻击命中后对相邻怪物造成50%溅射伤害 |
| BERSERKER_2 | 狂战士·嗜杀型 | `swift`（移动-1AP） | `awakened_frenzy`（狂热） | 击杀后下一击必定×3暴击并额外回复20HP（×10基准，原2） |
| ARCHER_1 | 射手·强击型 | `strengthen_attack_up`（攻击+5，×10基准，原+0.5） | `awakened_power_shot`（强弓） | 基础伤害额外+15（×10基准，原1.5） |
| ARCHER_2 | 射手·游击型 | `swift`（移动-1AP） | `awakened_volley`（连珠） | 连射概率提升至60%，命中后30%概率连锁射击 |
| ROGUE_1 | 隐匿者·屠戮型 | `strengthen_attack_up`（攻击+5，×10基准，原+0.5） | `awakened_execute`（处决） | 目标HP<30%直接处决，背刺伤害提升至3倍 |
| ROGUE_2 | 隐匿者·影袭型 | `eagle_eye`（攻击范围+1） | `awakened_shadow_strike`（影袭） | 每回合可触发2次背刺伤害 |

形态主题呼应：BERSERKER 觉醒形态借用 ARCHER（范围）/ROGUE（机动）的轻量词条，ARCHER/ROGUE 同理交叉借用，避免觉醒后与一阶词条重复。

## 六、状态效果 / Buff（DOT 与减益，ExpeditionState.endTurn 统一结算）

所有状态效果均存储为 `floorState` 上的"剩余回合数/累计值"字段，在每回合开始（`endTurn`）统一结算，结算顺序如下：

| 字段 | 来源 | 效果 | 持续/数值 |
|------|------|------|-----------|
| `playerFreezeRounds` | 第3章 Boss 冰霜巨人冰冻 | 当回合 AP 上限 `-FROST_GIANT_AP_PENALTY(4)`（最低1） | `FROST_GIANT_FREEZE_ROUNDS(1)` 回合 |
| `playerBurnRemaining` | 第4章 Boss 熔岩领主灼烧 | 每回合开始 -10 HP（`BURN_TICK`，×10基准，原-1），可叠加 | `LAVA_LORD_BURN_TICKS(3)`/次，无限叠加 |
| `playerFireBurnRounds`/`playerFireBurnAccum` | 赤炎哥布林（第1章变体）命中 | 每回合累计 +5（×10基准，原0.5），累计值跨过10的倍数时触发10点整数伤害 | `FIRE_BURN_ROUNDS(2)` 回合/次，可叠加 |
| `playerMoveApPenaltyRounds` | 冰霜哥布林（第1章变体）命中 | 移动消耗 +1 AP | `FROST_MOVE_PENALTY_ROUNDS(2)` 回合，可叠加 |

- 灼烧（`playerBurnRemaining`）优先结算；若已致死（`burnDead`），后续赤炎 DOT 不再叠加伤害但仍正常倒计时。
- 两类灼烧（Boss 整数 tick vs 变体怪 5/回合累计，×10基准，原0.5）独立计数，互不影响，可同时存在。
- 每回合开始还会重置：`shoesFirstMoveDone`（鞋子首步免费）、`shadowStrikeCount`（影袭可用次数归零）。

### 6.1a 第 4 章熔岩格（LAVA_TILE，地形而非玩家状态字段）

`floorState.entities` 中 `type='LAVA_TILE'` 的实体携带 `remaining` 剩余回合数，由 `endTurn` 统一结算：

- 每回合结束 `remaining -= 1`；玩家若站在该格上，扣 `CHAPTER4_LAVA_TILE_DAMAGE(5)` HP，emit `LAVA_TILE_DAMAGED`（可能 `PLAYER_DEAD`）。
- `remaining <= 0` 时移除该实体。
- 熔岩格的生成/刷新由 `lavaTideStep`（Boss 专属，详见 [Boss设计V1 §五](Boss设计V1.md)）驱动，与上表的玩家状态字段独立。

### 6.1 异常状态施加战报提示

玩家受到异常状态（非 Boss 专属冰冻/灼烧，详见 §9）时，在状态被**施加的当回合**额外 emit 提示事件（`monsterAttack`/`goblinChiefAttack` 中产生），与已有的 `FREEZE_APPLIED`/`BURN_APPLIED`（Boss 专属）形成统一覆盖：

| 事件 | 触发来源 | 文案 |
|------|----------|------|
| `MOVE_PENALTY_APPLIED` | 冰霜哥布林命中 / 哥布林酋长重击AOE命中 | 「🥶 被减速！接下来N回合移动消耗增加」 |
| `FIRE_BURN_APPLIED` | 赤炎哥布林命中 | 「🔥 中了灼烧！接下来N回合每回合持续扣血」 |

### 6.2 第 2-5 章地形/Boss 残血机制事件文案

| 事件 | 触发来源 | 文案 |
|------|----------|------|
| `SAND_PIT_STEPPED` | 玩家移动踩入沙坑（第2章 Boss 房） | 「🏜️ 陷入沙坑！移动 AP +1」 |
| `ICE_WALL_BROKEN` | 玩家攻击击碎冰墙（第3章 Boss 房） | 「❄️ 击碎冰墙！获得 1 灵气」 |
| `LAVA_TIDE_SPAWNED` | LavaLord HP≤50% 后每 `CHAPTER4_LAVA_TIDE_INTERVAL` 回合刷新熔岩 | 「🌋 熔岩潮汐！3 格被熔岩覆盖」 |
| `LAVA_TILE_DAMAGED` | 玩家踩在熔岩格上（回合结束结算） | 「🔥 被熔岩烫伤！-5 HP」 |
| `MIRROR_SPAWNED` | FateGuardian HP≤33% 生成镜像 | 「👥 命运镜像现身！」 |
| `MIRROR_KILLED` | 镜像被击杀（不掉落、不生成传送门） | 「✨ 击碎镜像！」 |

## 七、怪物 AI（MonsterAI.stepMonsters）

依次驱动场上全部存活怪各行动一次，玩家阵亡（`status==='DEAD'`）则提前终止。按怪物类型分派：

| 类型 | 行为模式 | 说明 |
|------|----------|------|
| `NORMAL` | IDLE → CHASE（进入仇恨范围）→ 攻击或贪心追击；离开范围回 IDLE | `stepToward` 按距离差更大的轴优先移动，受阻则换轴 |
| `ANIMA`（灵气怪） | 进入仇恨范围 → `FLEE`，按 `stepAwayFrom` 远离玩家；灵鼠（`VARIANT_SPIRIT_RAT`）每次移动2格，其余1格 | 无攻击能力（attack=0） |
| `ELITE`（精英怪） | 发现前 `PATROL`（确定性随机游走，`patrolDirIndex` 按 id+turn 散列）；发现后 `CHASE`（不返回 PATROL） | CHASE 后逻辑同 NORMAL |
| `BOSS` | 各章节专属机制（详见 [Boss设计V1](Boss设计V1.md)），`stepBoss` 优先于通用逻辑处理潜地/冒出/哥布林酋长完整行动序列 | — |

- **仇恨范围缩减**：ROGUE `stealth` 词条 -2，EPIC+ 鞋子额外 -2~3（`shoesStealthReduction`，可叠加），`inAggroRange = dist <= max(0, aggroRadius - 缩减)`。
- **占位判定**（`isOccupied`）：玩家位置 / 未消耗 `ROCK` 实体 / 其他存活怪物所在格均视为不可通行。

## 八、回合编排（ExpeditionState.endTurn）

```
endTurn:
  1. emit TURN_END
  2. stepMonsters（怪物行动一轮；玩家阵亡则提前返回 DEAD）
  3. 重新掷骰 rollAp → 叠加 strengthen_ap_up(+1) / treeBonuses.apDiceBonus
  4. 冰冻惩罚：AP 上限 -FROST_GIANT_AP_PENALTY（若 playerFreezeRounds>0）
  5. emit AP_ROLLED
  6. 灼烧结算（playerBurnRemaining → BURN_TICK；可能 PLAYER_DEAD）
  7. 赤炎DOT结算（playerFireBurnRounds/Accum → BURN_TICK；可能 PLAYER_DEAD）
  8. 移动惩罚倒计时 -1
  9. 重置 shoesFirstMoveDone / shadowStrikeCount
```

非 `ACTIVE` 或楼层非 `EXPLORING` 状态时整个 `endTurn` 为 no-op。

## 九、战报与事件回放（PveMessageLog + ExpeditionController._playEvents）

### 9.1 战报展示

详见 [UI设计与交互V1 §八](UI设计与交互V1.md#八战报栏pvemessagelog)：右侧/下方固定面板，预建 Label 节点池化，按 `LogKind`（`PLAYER_ACT`/`PLAYER_HURT`/`ENEMY_ACT`/`LOOT`/`AP`/`SYSTEM`）上色，同回合内仅首行显示"回合N"前缀。

### 9.2 事件回放节奏

`ExpeditionState` 各 `apply*` 函数返回 `PveEvent[]`（`PveTypes.ts` 定义约 30 种事件类型，覆盖移动/揭示/攻击/击杀/掉落/拾取/AP/状态效果/职业进阶与觉醒/装备/成就/Boss专属机制/命运树选择等），由 `ExpeditionController._playEvents` 串行播放：

- 每个有文案的事件 → 先 `toast` 再 `await delay(...)`，期间 `_busy=true`，玩家输入被丢弃且无反馈。
- 调优后的延迟：事件间隔 `delay(120ms)`（原250ms）；自动结束回合过渡 `delay(80ms)`（原150ms）；强反馈节点（灵气强化生效/楼层通关/Boss战）保留 420ms~2000ms 的较长停顿。
- **怪物发现/击杀文案补偿**（M1 无进场动画/弹窗）：
  - `REVEAL` 事件揭示格中含存活怪物 → 追加 `ENEMY_ACT`「👀 发现 怪物名！」（多个用顿号分隔）。
  - `KILL` 事件 `PLAYER_ACT` 文案为「💀 击杀了 怪物名」，对应 toast 为「击败了 怪物名！」。

## 十、性能与确定性约束

- **节点池化**：`FogMapView`（地图格子）、`PveMessageLog`（战报条目）均预建固定数量节点常驻复用，仅 diff 内容变化时重绘，禁止每次 `refresh` 销毁重建（参考 `BoardView` 既有模式）。
- **确定性 RNG（AC-13）**：所有概率判定（暴击/连射/连锁/精英掉落等）通过 `createRng(floorState.rngState)` 派生，无论判定结果是否触发都 `rng.state()` 写回，保证"相同 runSeed + 相同操作序列 → 相同结果"，供客户端模拟与云端复算比对。
- **纯函数边界**：`MovementSystem`/`CombatSystem`/`ApSystem`/`MonsterAI`/`ExpeditionState` 均零 `cc` 依赖，`ApplyResult = { state, events }`，状态不可变更新（spread），便于单测（`test/` 下 ts-jest）与服务端镜像复用。
