## 一、定位

本文档覆盖「局内养成的数值如何产生」与「局外如何持久化」两条线：

- **局内养成（单局有效，死亡清空）**：装备生成（`EquipmentSystem`）、灵气强化（`AnimaSystem`）、铁匠服务（见 [地图与探索系统V1](地图与探索系统V1.md) §5.1）。
- **局外养成（账户级永久）**：成就/图鉴（`AchievementSystem`）、命运碎片与命运树（详见 [命运树设计V1](命运树设计V1.md)）。
- **存档与结算架构**：客户端模拟 + 云端校验/奖励发放/元进度持久化（`PveSave`/`PveValidate`/`PveReward`/`PveMeta`）。
- **RNG 种子体系**：`rng.ts` + `hashSeed`，决定"同 seed 必然复现"的确定性范围。

## 二、装备系统（EquipmentSystem）

### 2.1 槽位与品质

5 槽位 × 5 品质阶模板表（`EQUIPMENT_TEMPLATES`），各槽位 `baseStat` 含义不同：

| 槽位 | baseStat 含义 |
|------|------|
| 武器（WEAPON） | 攻击力加成，参与 [战斗系统V1](战斗系统V1.md) §4.1 玩家攻击力计算（`playerAttackPower`） |
| 护甲（ARMOR） | 受伤减伤值，在怪物攻击伤害结算时扣减（`monsterAttack`） |
| 头盔（HELMET） | 最大生命值加成（生效于 `EquipHelper.equipItem`：装备/替换/铁匠强化时按 baseStat 差值调整 maxHp，升级或首次装备同步上抬 hp） |
| 鞋子（SHOES） | 移动相关效果阈值（见 §2.2），同时也是占位基础属性 |
| 饰品（TRINKET） | 灵气获取加成百分比（`baseStat` 直接作为百分比，见 [数值系统V1](数值系统V1.md) §八，由灵气强化系统的获取加成计算读取，对应 `AnimaSystem.addAnima`） |

具体数值表见 [数值系统V1](数值系统V1.md) §六。

`rollEquipment(rng, slot, quality)`：按模板生成实例，`id` 由 `rng.int(10000,99999)` 生成唯一后缀（保证同种子确定性）。`rollRandomSlot(rng)`：5 槽位等概率随机选取。

## 三、灵气强化系统（AnimaSystem）

### 3.1 触发与阈值

- 灵气来源：怪物掉落、宝箱、祭坛（见 [地图与探索系统V1](地图与探索系统V1.md) §6），经 `addAnima(state, amount)` 计入 `player.anima` 与 `player.animaProgress`。
- 饰品（TRINKET）的 `baseStat` 直接作为灵气获取加成百分比；命运树 D3「灵气亲和」追加 `treeBonuses.animaGainBonusPct`；两者相加后对 `amount` 取整加成。
- 当 `animaProgress >= animaThreshold` 时触发一次 `STRENGTHEN_CHOICES=3` 选 1（`ANIMA_STRENGTHEN` 事件携带 `choices`），消耗阈值后 `animaThreshold ×= ANIMA_THRESHOLD_MULTIPLIER(1.5)`：初始 100 → 150 → 225 → 337...
- 单次大额获取（如祭坛一次给 35、但叠加后超过阈值差额）可在同一次 `addAnima` 调用中**连续触发多次** 3 选 1（`while (progress >= threshold)` 循环）。

### 3.3 应用强化 `applyStrengthen`（AC-405/406）

- 每条词条在 `STRENGTHEN_META` 中标注 `tier`（basic/condition/stack/advanced）与可选的 `stack`（叠加上限，缺省 1）/ `oneShot`（一次性）。
- **stack 限制**：`classTraits` 中该词条数量 ≥ `stack` 上限时，候选池过滤掉该词条（不会被抽到），`applyStrengthen` 对其也是 no-op。
- **oneShot**：已选过一次后，候选池过滤、`applyStrengthen` 均为 no-op。
- **advanced 解锁**：`tier='advanced'` 的词条仅当玩家已拥有 ≥3 个同池 `tier∈{basic,condition}` 的词条时才会出现在候选池中。
- 立即生效词条：`strengthen_hp_up`（+40）、`iron_skin_stack`/`quiver_stack`/`nimble_stack`（每层 +3）选中时立即调整 `maxHp`/`hp`（不超过新 maxHp）。
- 其余词条计入 `player.classTraits`，由 [战斗系统V1](战斗系统V1.md)/`MovementSystem` 在对应计算点读取生效。

## 四、成就与图鉴（AchievementSystem）

### 4.1 成就定义（8 个，账户级永久解锁）

| id | 名称 | 解锁条件 |
|------|------|------|
| FIRST_EXPEDITION | 踏上命运之旅 | 第1层第1回合 `AP_ROLLED` |
| FIRST_KILL | 初战告捷 | 首次 `KILL` |
| FIRST_CHEST | 寻宝者 | 首次 `OPEN_CHEST` |
| FIRST_EQUIPMENT | 初露锋芒 | 首次 `LOOT` 携带 `equip` |
| CLASS_ADVANCED | 职业觉醒 | 首次 `CLASS_ADVANCED` |
| CHAPTER_1_CLEARED | 第一章英雄 | `FLOOR_CLEARED` 且 `floor===5` |
| REACH_FLOOR_10 | 深入探索 | 任意楼层 `AP_ROLLED` 时 `floor>=10` |
| FULL_CLEAR | 命运征服者 | `FLOOR_CLEARED` 且 `floor===25` |

`checkNewAchievements(events, floor, unlocked)`：纯函数扫描本轮事件，返回**本轮新解锁**且未在 `unlocked` 中的成就 id 列表（去重幂等）。

### 4.2 图鉴条目提取

`collectCodexEntries(events)`：从事件中提取 `{ monsters: string[], equipment: string[] }`——`KILL.monsterType` 与 `LOOT.equip.slot`，可能含重复，调用方负责去重合并到 `users.pveCodex`。

### 4.3 持久化

成就/图鉴属于**局外永久数据**，存储在 `users` 集合：`users.achievements`（已解锁 id 列表）、`users.pveCodex`（`{monsters, equipment}`）。由 `PveMeta.updateMeta` 幂等追加（详见 §六）。

## 五、RNG 种子派生体系（rng.ts）

### 5.1 算法

`createRng(seed)` 基于 mulberry32（32位、快速、分布良好），对外暴露 `next/int/chance/pick/shuffle/state`。`pve/core` 内**禁止直接调用 `Math.random()`**，所有随机均须经传入的 `Rng` 实例，确保同种子可复现、云端可复算（AC-13）。

`hashSeed(input: string|number)`：FNV-1a 风格字符串哈希 → 32位无符号整数，用于从字符串模板派生子种子。

### 5.2 种子层级

```
runSeed（远征级，开局时由云函数 pve action startRun 服务端生成并下发，AC-503/504）
 ├─ deriveTreeRng(runSeed)        = createRng(hashSeed(`${runSeed}:tree`))
 │     → 命运树 E2/E3 待选项 3选1（startExpedition 时一次性固化为 pendingTreeChoices）
 │
 └─ deriveFloorSeed(runSeed, floor) = hashSeed(`${runSeed}:floor:${floor}`)
       → generateFloor(floor, seed) 生成该层地图布局
       → floorState.rngState 在层内续算（移动/攻击/掉落/祭坛/铁匠洗炼等所有层内随机均消耗并推进此状态）
```

- **runSeed**：一次远征唯一，存档持久化字段，由云函数 pve action `startRun` 服务端生成并下发（已有活跃存档时返回其 runSeed 用于续局），之后全程不变（服务端 `validateSaveFloorReport`/`validateSettleReport` 校验 `runSeed` 不可中途变更）。
- **每层独立种子**：`deriveFloorSeed` 保证各层布局确定且互不干扰；`resumeExpedition`/`advanceFloor` 均按相同公式重新派生，云端可按 `runSeed+floor` 复算出相同地图（AC-13）。
- **命运树 RNG**：与楼层 RNG 完全独立的子种子，避免命运树待选项随玩家在层内的随机操作次数而漂移。

## 六、存档与云端校验架构

### 6.1 总体流程

客户端按 [战斗系统V1](战斗系统V1.md) 的 `ApplyResult` 纯函数模式在本地模拟整局战斗，**仅在关键节点**（完成一层 / 远征结束）向云端 `pve` 云函数上报：

```
loadActiveSave  → 进入远征前读取 pve_saves（无存档则 _beginNewRun，有存档则 _resumeRun）
saveFloorProgress → 每层 FLOOR_CLEARED 后整份覆盖写入 ExpeditionState 可序列化字段
settleExpedition  → 死亡(DEAD)或通关(COMPLETED)时结算奖励、清除存档
```

### 6.2 存档结构（PveSave.toSaveVO）

```ts
{
  runSeed: number,
  status: 'ACTIVE' | ...,
  chapter: number,
  floor: number,
  player: RunPlayer,        // 含装备/职业/灵气进度/命运树加成等
  floorState: FloorState | null,
  updatedAt: timestamp,
}
```

写入时使用 `version` 做乐观锁（`putPveSave(user.id, patch, current?.version)`）。

### 6.3 服务端校验（PveValidate）

| 校验函数 | 规则 | 失败 code |
|------|------|------|
| `validateSaveFloorReport` | `floor` 为正整数；无存档时 `floor` 必须为 1（新远征）；有存档时 `runSeed` 必须与存档一致、`floor` 必须恰好为 `save.floor + 1`（不可跳层/回退） | `PVE_INVALID_FLOOR` / `PVE_INVALID_SEED` / `PVE_FLOOR_DISCONTINUITY` / `PVE_SEED_MISMATCH` |
| `validateSettleReport` | `status` 必须是 `DEAD`/`COMPLETED`；无存档时 `floor` 必须为 1；有存档时 `runSeed` 一致，且 `save.floor <= floor <= save.floor+1`（死亡可能发生在到达新层、尚未存档之时） | 同上 |

所有校验失败抛出带 `code` 的 `Error`，由云函数统一转换为 `{ ok:false, code, message }`。

### 6.4 结算奖励（PveReward，纯服务端计算）

`computeSettleReward(finalFloor, status)`：**完全不信任客户端上报的奖励数值**，仅按"已通关层数"服务端纯计算：

- `floorsCleared = status==='COMPLETED' ? finalFloor : max(0, finalFloor-1)`（死亡时当前层未完成，只计已通过层数）
- `bossFloors = floor(floorsCleared / PVE_FLOORS_PER_CHAPTER(5))`
- `diamond = floorsCleared × 1(DIAMOND_PER_FLOOR) + bossFloors × 3(DIAMOND_PER_BOSS_FLOOR)`
- `destinyShards = floorsCleared × 1(SHARD_PER_FLOOR) + bossFloors × 2(SHARD_PER_BOSS_FLOOR)`

钻石与命运碎片通过 `incrementUserPveRewards` 写入 `users` 集合；命运碎片为 PVE 专属局外资产，钻石账户与 PVP 共享。结算后删除 `pve_saves` 记录（下次进入视为新远征）。

### 6.5 局外元进度（PveMeta）

存储于 `users` 集合同一文档：

| 字段 | 内容 | 写入方 |
|------|------|------|
| `users.destinyShards` | 命运碎片余额 | `settleExpedition` 累加 / 命运树解锁时扣减 |
| `users.achievements` | 已解锁成就 id 列表 | `updateMeta` 幂等追加 |
| `users.pveCodex` | `{ monsters: string[], equipment: string[] }` | `updateMeta` 幂等追加 |
| `users.unlockedTreeNodes` | 已解锁命运树节点 id 列表 | `unlockTreeNode`（权威校验，详见 [命运树设计V1](命运树设计V1.md)） |

`loadMeta`/`updateMeta`/`unlockTreeNode` 对应 `pve` 云函数 action：`loadMeta` / `updateMeta` / `unlockTreeNode`。新用户字段不存在时返回安全默认值。
