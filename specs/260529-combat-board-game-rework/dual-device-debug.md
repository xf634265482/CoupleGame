# 双端联调步骤（微信开发者工具 × 2）

> 对应 `acceptance-checklist.md` 中「双端联调清单」与 **AC-20** 目视验收。  
> 预计耗时：30～45 分钟（含首次部署云函数）。

---

## 0. 联调前准备

### 0.1 构建与配置

1. **Cocos Creator** → 构建发布 → 微信小游戏（输出 `build/wechatgame/`）。
2. 确认 `config/wechat.local.json` 已填写 `appId`、`cloudEnvId`（与 `assets/scripts/core/Constants.ts` 中 `CLOUD_ENV_ID` 一致）。
3. 根目录 `project.config.json` 的 `appid` 与上述 AppID 一致。

### 0.2 部署云函数（改版后必做）

```bash
# 仓库根目录
node scripts/sync-cloud-common.js
```

在微信开发者工具 → **云开发** → **云函数**，对以下函数执行 **上传并部署：云端安装依赖**（至少）：

| 函数 | 说明 |
|------|------|
| `login` | 登录 |
| `room` | 建房 / 加入 / 开始 |
| `match` | 匹配（可选） |
| `game` | 棋盘全部 action |
| `initDb` | 首次环境初始化（若未跑过） |

### 0.3 打开两个开发者工具实例

| 实例 | 建议命名 | 作用 |
|------|----------|------|
| **A** | 房主 | 创建房间、开始游戏 |
| **B** | 客人 | 加入房间 |

操作：

1. 启动微信开发者工具，导入项目（根目录或 `build/wechatgame`，与 `project.config.json` 一致）。
2. 再启动**第二个**开发者工具窗口，导入**同一项目**（或复制一份工程到另一路径，避免文件锁冲突）。
3. 两个窗口都选择同一 **云开发环境**（右上角云开发图标 → 环境 ID 一致）。

### 0.4 确保是两个不同玩家（重要）

小游戏内 `wx.cloud.callFunction` 会带各自模拟的 **OPENID**。若两端显示为同一昵称/同一座位：

- 开发者工具 → **详情** → **本地设置** → 尝试 **清除缓存** 后重新编译；
- 或使用 **多账号调试**（工具菜单 / 真机调试里切换不同测试微信号）；
- 勿在控制台用同一个 `testOpenId` 测 `room`/`game` 后又用模拟器进房（会串号）。

**验收标准**：大厅顶部或房间内玩家列表应出现 **2 个不同昵称**，座位 0、座位 1。

## 1. 开局：同一 `gameId`

| 步骤 | 实例 A（房主） | 实例 B（客人） |
|------|----------------|----------------|
| 1 | 编译运行，进入大厅 | 编译运行，进入大厅 |
| 2 | 点 **创建房间** → 选 **2 人** | 记下 A 界面上的 **6 位房间号** |
| 3 | 等待 B 加入 | 输入房间号 → **加入房间** |
| 4 | 确认房间显示「2/2 人」 | 同上 |
| 5 | 点 **开始游戏** | 自动跳转棋盘（watch `room` → `PLAYING`） |

**核对 `gameId`（可选但推荐）**：

1. 云开发控制台 → **数据库** → `games` 集合。
2. 按 `updatedAt` 倒序，打开最新一条文档，记下 `_id`（即 `gameId`）。
3. 两端进入棋盘后，在调试器 Console 执行（若已暴露）或看网络：应对局同一文档。

两端均应看到：

- 横版 **75 格** 棋盘（`BoardView`）；
- 底部 HUD **四按钮**：投骰、道具、攻击、结束；
- 玩家卡：**HP 10/10**、金币、钻、装备/道具行。

勾选：`acceptance-checklist` → **两实例 watch 同一 gameId**（前半）。

---

## 2. 联调项 1：掷骰与 watch 同步

**操作（当前回合玩家，一般为座位 0）**

1. 点 **投骰**，等待骰子 toast + 棋子移动动画结束。
2. 观察 **非当前回合** 的实例 B：应在数秒内看到对方棋子移动、HUD 金币/HP 变化。

**预期**

| 检查点 | 通过标准 |
|--------|----------|
| 骰子范围 | 1～6（无「掷 7 再掷」） |
| 回合不自动切换 | 投骰后仍为本回合，直至点 **结束** 或继续道具/攻击 |
| 对方画面 | B 能看到 A 的骰子 toast（或移动动画），数据与 A 一致 |
| 状态栏 | 本回合方显示 `骰✓` 等行动标记（AC-20） |

**失败排查**

- B 长时间不更新：看 Console 是否有 watch 报错；确认 `game` 云函数已部署；Board 场景有 4s 轮询兜底。
- 报错 `NOT_YOUR_TURN`：仅当前 `currentSeat` 可投骰。

---

## 3. 联调项 2：路径事件 toast / 战斗日志

**操作**

1. 多掷几轮，故意走经 **金币格、事件格、幸运格** 的路径（可多局）。
2. 当前回合玩家侧：看上方面板 **战斗日志**（最多约 5 行）与格子 **toast**。

**预期**

- 路径经过多格时，事件顺序与云端 `lastEvents` 一致（先经过先展示）。
- 对方实例能看到 **远程掷骰 toast** 和格子相关提示（文案含「你」/对方昵称）。

勾选：**路径多格事件 toast / 战斗日志顺序正确**。

---

## 4. 联调项 3：商店购买

**操作**

1. 若本局金币不足，可在云库 `games` 文档里临时把该玩家 `players[n].gold` 改为 `5000`（仅测试环境），或多次踩金币格。
2. 踩 **金币商店** 或 **传说商店** 格（绿/紫色格，字「店」「传」），应弹出商店 modal。
3. 购买 **剑（1200 金）** 或 **枪（8 钻）**。

**预期**

| 检查点 | 通过标准 |
|--------|----------|
| 扣费 | 金币/钻减少，与标价一致 |
| 装备 | HUD 显示武器（距/伤） |
| 库存 | 同商品再次打开为售罄；**路过**同类型商店后刷新 |
| 云端 | `games` 文档 `players[].weapon`、`gold`、`shopStock` 已更新 |

勾选：**踩商店格弹出购买，资源与装备一致**。

---

## 5. 联调项 4：小游戏 → 回棋盘（多行动回合）

**操作**

1. 当前回合玩家踩 **小游戏格**（「戏」），在倒计时内点 **进入**。
2. 完成一局吹牛（摇骰 → 叫点 → 开牌，直到结束）。
3. 自动回到 **棋盘** 场景。

**预期**

- 回到棋盘后 **仍为触发小游戏前的 `currentSeat`**（一般为踩格玩家）。
- 若进小游戏前 **已投骰**：**投骰/再掷** 为灰色，**道具、攻击、结束** 仍可用（`turnActions.rolled=true` 保留）。
- 若进小游戏前未投骰：仍可投骰。

勾选：**踩小游戏 → 吹牛 → 回棋盘行动规则正确**。

---

## 6. 联调项 5：攻击、中立生物、淘汰、结算

### 6.1 买武器并攻击玩家

1. 商店买 **剑**，结束回合换对方。
2. 对方买剑、移动至 **距离 ≤2** 的格子。
3. 点 **攻击** → 选另一玩家。

**预期**：对方 HP 减少；战斗日志有伤害文案；`turnActions.attacked=true`。

### 6.2 攻击中立生物

1. 移动到某一 **区域**（棋盘分 3 区，中立 HP 显示在区域中央）。
2. 装备武器后 **攻击** → 选「中立生物」。

**预期**：中立 HP 下降；最后一击 +2000 金、道具（日志可见）。

### 6.3 淘汰与结算（2 人局最快）

1. 连续攻击直至对方 HP≤0，或对方 **退出**。
2. 应自动进入 **结算页**。

**结算页检查（AC-18、AC-19、AC-20）**

- 胜者标记、排名；
- 每行含 **HP、击败数、金币、局内钻、资源值**；
- 脚注「局内钻石不计入局外余额」；
- **不**强调「局外钻石 +N」（除非你们另行开启写回）。

勾选：**攻击/淘汰/结算页字段正确**。

---

## 7. 联调项 6：AC-21 客户端不可篡改

**目的**：确认 HP/金币 只能由服务端改变。

1. 在 **当前回合玩家** 的开发者工具 → **调试器** → **Console**（棋盘场景已加载）。
2. 尝试本地改镜像（仅测试，不应影响真服）：

```javascript
// 若全局未暴露，可在 Sources 里对 GameStateMirror 下断点改值；
// 或在临时调试代码中：
// GameStateMirror.setGame({ ...game, players: [...] })  // 把 hp 改成 99
```

3. **不要点任何按钮**，等待 4～8 秒（Board 轮询拉取）或让对方操作触发 watch。
4. 或自己点 **投骰/结束** 后看 HP 是否被云端覆盖。

**预期**：本地改成 99 的 HP，刷新/操作后恢复为云端真实值；云库 `games` 文档中 `hp` 未被改成 99。

勾选：**本地改镜像不影响云端（刷新后恢复）**。

## 8. AC-20 目视检查表（HUD）

在棋盘场景对 **己方玩家卡** 与 **状态栏** 逐项打勾：

| 项 | 位置 | 通过 |
|----|------|------|
| HP | 玩家卡主行 | `HP x/10` |
| 击杀 | 玩家卡主行 | `杀n` |
| 武器 | 主行 | 有武器时显示距/伤（如 `剑 距2 伤1`） |
| 护甲/鞋 | 副行 | 盔/铠减免、行军鞋 |
| 金币/钻 | 副行 | `金x 钻x` |
| 道具数量 | 副行 | `骰/陷/包` 数量 |
| 行动剩余 | 顶栏（己方回合） | `骰○/✓ 道具○/✓ 攻○/✓` |
| 四按钮 | 底栏 | 非回合灰色；回合内按规则亮/灰 |
| 淘汰态 | 玩家卡 | 名称带「淘汰」 |

全部通过后，可将 `design.md` 中 **AC-20** 勾选为 `[x]`。

## 10. 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 加入房间失败 | `room` 未部署 / 环境 ID 不一致 | 核对云环境与 Constants |
| 开始游戏无反应 | 未满员 / 非房主点开始 | 2 人房需 2 人，A 点开始 |
| 棋盘空白 | 未构建或场景未包含 board | Cocos 构建并确认 `board` 场景 |
| 按钮全灰 | 非 `currentSeat` 或已淘汰 | 看 HUD 顶栏当前回合名 |
| `NOT_IMPLEMENTED` | `game` 未同步 common | 运行 `sync-cloud-common.js` 再部署 `game` |
| 两端同一人 | OPENID 相同 | 清缓存 / 多账号调试 |
| watch 不推送 | 数据库权限或网络 | 控制台看 `games` 是否更新；依赖 4s 轮询 |
