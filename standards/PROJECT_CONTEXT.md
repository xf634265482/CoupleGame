# PROJECT_CONTEXT — 命运之塔（Fate Tower）

## Purpose

让任何首次接入项目的 AI / 人，在 10 分钟内建立对《命运之塔》的正确心智模型：
- 这是什么游戏
- 给谁玩
- 核心体验是什么
- 与本仓库历史代码的关系（PVP / PVE 双玩法共存）
- 当前阶段与必须遵守的边界

本文件 **不** 涉及实现细节；实现细节归 `specs/` 与 `02_Programming/`。

## Standards

### 1. 项目身份

| 项 | 值 |
|----|----|
| 中文名 | 命运之塔 |
| 英文名 / 工作代号 | Fate Tower（原 PVE Destiny Expedition） |
| 类型 | 微信小游戏 · 单人 PVE · 迷雾爬塔 + Roguelite |
| 引擎 | Cocos Creator 3.8.8 |
| 后端 | 微信云开发（云函数 + 云数据库） |
| 平台 | 微信小游戏（主战场） · 后续考虑 H5 / 抖音小游戏 |
| 目标设备 | 中端及以上 Android / iOS 微信，屏幕 5.0"~6.7" |
| 主包红线 | 4 MB（微信主包限制；分包另算） |

### 2. 与本仓库历史代码的关系

本仓库历史上同时承载两套独立玩法：

- **PVP**：联机派对棋盘对战（云端权威）→ 已暂停，不再扩展
- **PVE**：单人「命运远征」迷雾爬塔（客户端模拟 + 云端校验）→ **= 命运之塔**，**当前唯一在研玩法**

> **结论**：本规范库 = 命运之塔规范库 = PVE 规范库。
> 涉及 PVP 的现存代码与资源**保持原样**，不删除（见 `AI_AGENT_RULES.md` F2 / R4），也不为命运之塔做风格统一改造。

### 3. 核心设计理念（Design Pillars）

> 任何玩法 / 美术 / UI 决策若与以下任一条冲突，必须停下来与设计裁决。

#### P1 — 迷雾下的取舍（Fog of Choice）
- 玩家在视野受限的格子地图上推进，每一步都是不完全信息下的决策。
- 视野扩张本身是资源，"看清"与"前进"是两种代价。
- 设计上禁止用全局小地图破坏迷雾紧张感。

#### P2 — 一步一个结局（Step-Scale Drama）
- 每一格的事件（战斗 / 宝箱 / 陷阱 / 商店 / 事件）都是一次小型剧场。
- 每个事件的结果在 5~15 秒内反馈，避免"无意义走格子"。
- 单局节奏目标：玩家在 15~25 分钟内完成一次远征。

#### P3 — 命运的累积（Destiny Carries Over）
- 单局之外有元进度（命运树），让"失败"也能转化为长期成长。
- 元进度永远不应让玩家在单局中"碾压"内容，只改变可用工具组合。

#### P4 — 一眼能读的画面（Phone-First Readability）
- 玩家在 5~6 寸屏幕、单手操作、可能 60% 注意力下游戏。
- 任何角色 / 怪物 / 图标在 ≤ 100 px 显示下必须可分辨身份。
- 见 `03_Art/Character_Art_Guide.md` §10。

#### P5 — 客户端先行模拟，云端最终判定
- 单人体验追求"零网络感"，所有玩法核心在本地纯函数模拟。
- 关键节点（关卡完成 / 奖励发放 / 元进度变更）由云端校验回放，防作弊。
- 见 `02_Programming/Code_Architecture.md`。

#### P6 — AI 是协作者，不是创作者
- AI 用于生产、检查、补全，**不用于**自主创造世界观、角色身份、玩法主轴。
- 所有 AI 输出必须被人类决策审批后才进入项目。

### 4. 世界观一句话定位

> **古老的命运之塔在迷雾深处升起；勇者循着血脉的指引一层层攀登，每一层都是命运给他的一次审判。**

- 调性：**轻奇幻 · 童话史诗**（不黑暗、不血腥、不写实战争）
- 情感基底：希望 · 探险 · 命运感（不绝望、不猎奇）
- 视觉关键词：明亮天空塔庭 · 棕发蓝金冒险者 · 青色命运晶体 · 柔金纹章 · 深海军蓝轮廓 · 半厚涂轻奇幻
- 文化底色：**泛欧亚奇幻**，避免明显的单一民族/地缘指向

### 5. 玩家画像

| 维度 | 主要玩家 | 次要玩家 |
|------|---------|---------|
| 年龄 | 18~35 岁 | 13~17 岁、35~45 岁 |
| 设备 | 微信小游戏，中端手机 | 同上 |
| 游戏经验 | 玩过《杀戮尖塔》《忘川风华录》《以闪亮之名》《地下城堡》《不思议迷宫》中至少一款 | 较少 Roguelite 经验，习惯休闲卡牌 / 二次元抽卡 |
| 期望单次时长 | 15~25 分钟（一次远征） | 5~10 分钟（一段路） |
| 留存动力 | 元进度收集 · Build 探索 · 章节叙事 | 角色养成 · 美术体验 |

### 6. 关键边界（Hard Constraints）

| 类别 | 约束 |
|------|------|
| 平台 | 微信主包 ≤ 4 MB；分包 ≤ 4 MB / 个；总大小 ≤ 30 MB |
| 性能 | 中端机 60 FPS 战斗 / 30 FPS 探索；冷启动 ≤ 5s |
| 法规 | 不出现现实宗教、政治符号；不出现成人 / 赌博 / 暴力血腥内容 |
| 美术 | 全项目统一同一套视觉语言（见 `03_Art/Character_Art_Guide.md`） |
| 网络 | 单人玩法必须支持弱网 / 短时断网继续游玩；恢复后由云端校验 |
| 隐私 | 不收集除微信 openId 与必要游戏数据外的用户信息 |

## Examples

### 正确：理解项目身份后开始任务
> 用户问："帮我设计第 2 章的新怪物"
> AI：读 `PROJECT_CONTEXT.md` → 知道是命运之塔 PVE、轻奇幻调性、5~6 寸屏可读 → 读 `01_Game_Design/Monster_Design.md` 与 `03_Art/Character_Art_Guide.md` → 才开始设计。

### 错误：跳过上下文直接设计
> AI：直接生成"暗黑写实风的腐尸怪兽"→ 违反 P4 调性 / 视觉语言；违反 R7 / R8 美术统一。

### 正确：玩家询问跨玩法概念时澄清
> 用户："给棋盘对战加个怪物"
> AI：先确认"棋盘对战"是历史 PVP 玩法，命运之塔当前不在 PVP 上扩展，是否确实要碰 PVP 代码？

### 错误：默认 PVP/PVE 通用
> AI：在 PVE 路径下加一段 PVP 联机逻辑，把两套玩法搅在一起。

## AI Notes

- 当用户提到"游戏"、"项目"、"我们这个"，默认指**命运之塔（PVE）**；除非上下文明显是历史 PVP。
- 设计灵感参考：《杀戮尖塔》（节奏感）、《不思议迷宫》（迷雾爬塔）、《忘川风华录》（轻奇幻立绘感）、《Cult of the Lamb》（chibi 比例参考），但**不抄风格**。
- 任何"加 PVP 模式"、"加联机"、"加排行榜"、"加抽卡"、"加充值"诉求，必须先与用户确认是否纳入路线图（见 `07_Project/Development_Roadmap.md`），不要默认排进 backlog。
- 涉及"是否符合调性"的判断（例如怪物长相是否过黑暗），AI 必须显式调用本文件 §3 P1~P5 与 §6 来评估，**不要凭模型直觉**。
