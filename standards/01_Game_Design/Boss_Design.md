# Boss_Design — Boss 设计原则

## Purpose

定义"什么是一个合格的命运之塔 Boss"，避免 Boss 沦为"高血量普通怪"。

## Standards

### 1. 一个合格 Boss 必须满足

| 条件 | 描述 |
|------|------|
| 标志性外观 | 满足 `03_Art/Character_Art_Guide.md` §3 / `04_AI/Boss_Prompt_Template.md` |
| 标志性机制 | 1 个可被识别、可被破解的核心机制 |
| 2~3 阶段 | 战斗推进有节奏（如 50% HP 变形） |
| 公平 telegraph | 大招前有至少 1 个预警回合 |
| 击败仪式感 | 死亡动效 + 章节结算特别动画 |

### 2. 机制类型库

| 类型 | 例 |
|------|----|
| 元素压制 | 全场火/冰；只能被克元素打高 |
| 阶段变身 | HP 阈值变形 + 重置状态 |
| 召唤 | 召小怪需先清完 |
| 区域伤害 | 跨回合预警的全场技 |
| 反伤 | 普攻反弹 N%；逼玩家用卷轴 |
| 移除增益 | 解除玩家 Buff，逼玩家适应 |
| 锁定移动 | 玩家不能走（专心战斗） |

每个 Boss **取 1 个主机制 + 至多 1 个辅机制**，**不堆机制**。

### 3. 数值红线

- Boss HP ≤ 玩家平均章节末 ATK × 30（保证 2~4 分钟可解）
- Boss 单次伤害 ≤ 玩家章节末 HP × 0.4（避免一击秒）
- Boss DEF ≤ 玩家 ATK × 0.5（避免"打不动"）

### 4. 公平性

- 大招必须有 telegraph（红色警告 / 角色动作变化）
- Boss 行动按固定 pattern 或显式优先级（不纯随机）
- 玩家有"识破套路"的可能性

### 5. 章节 Boss 主题

| 章节 | Boss 主题（参考） |
|------|----------------|
| 1 | 哥布林酋长（蓄力重击 + 增援号角） |
| 2 | 流沙巨蝎（潜地突袭 + 流沙扩张 + 沙暴） |
| 3 | 冰霜巨人（寒气 + 冻结） |
| 4 | 熔岩领主（灼烧印记 + 喷发预警 + 熔岩潮汐） |
| 5 | 终塔最终 Boss（综合机制 + 多阶段） |

> 具体 Boss 行为走 `specs/`，本节定义骨架。

### 6. 不允许

- ❌ 单一血条无机制的"沙包 Boss"
- ❌ 战斗 > 4 分钟
- ❌ 大招无 telegraph
- ❌ 机制堆叠 ≥ 3 个
- ❌ 数值碾压（玩家"无论怎样都打不过"）

## Examples

### 正确
> 第 2 章流沙巨蝎：通过潜地预兆、流沙扩张和沙暴范围建立可识别威胁；第 4 章熔岩领主通过喷发预警和熔岩潮汐建立可规划的场地压力。具体数值以 `specs/260608-pve-destiny-expedition/design.md` 与对应 Boss 文件为准。

### 错误
> 设计一个 Boss：HP 3000，每回合随机大招，无预警 → 违反 §1 / §4 / §6

## AI Notes

- 设计 Boss 前必读 §2 机制库；不要新创"我觉得有趣的"机制
- 与美术沟通时强调 §1 标志性外观
