# Performance_Guidelines — 性能规范

## Purpose

让《命运之塔》在中端微信小游戏机型上达成稳定 60 FPS 战斗 / 30 FPS 探索，冷启动 ≤ 5s。

## Standards

### 1. 帧率目标

| 场景 | 目标 FPS | 不允许 |
|------|---------|--------|
| 大厅 | 60 | 任何掉帧 |
| 战斗 / 移动 | 60 | 卡顿超过 100ms |
| 弹窗 / 结算 | 60 | 同上 |
| 章节切换 | 30 (短暂) | 黑屏超过 1.5s |

### 2. 包体红线

| 项 | 上限 |
|----|------|
| 主包 | 4 MB |
| 单分包 | 4 MB |
| 总包 | 30 MB |
| 启动必加载 | 2 MB |

### 3. 渲染预算

| 项 | 上限 |
|----|------|
| 单帧 DrawCall | 60 |
| 同屏 Sprite 数量 | 200 |
| 同屏粒子 | 50 |
| 文本节点 | 30 |

### 4. 代码层

- 避免每帧创建对象（造成 GC 抖动）
- 池化频繁创建的飘字 / 受伤数字
- `update` 中不做 O(n²) 检查
- 计时器优先用 Cocos `Tween` / `schedule`，不裸 `setInterval`

### 5. 资源层

- 单 PNG 源尺寸 ≤ 1024×1024；UI/icon ≤ 512
- PNG 启用 `tinypng` 类压缩；UI 透明 PNG 不超 100 KB
- 不上 PSD / Layered 资源；只入库扁平 PNG
- 音频用 `m4a`；BGM ≤ 200 KB；SFX ≤ 30 KB

### 6. 网络

- 单云函数响应目标 ≤ 800ms
- 弱网下客户端先模拟、云端异步校验
- 重试退避：1s → 2s → 4s，3 次后报错

### 7. 启动优化

- 主场景 onLoad ≤ 300ms
- 启动只加载必要 UI 与登录
- 章节资源懒加载

### 8. 排查规则

> 性能 / 渲染 / 资源类问题适用 `AI_AGENT_RULES.md` R6 系统化排查。

- 先用真机 / 微信 devtools profile，不要先改代码
- 每步只验证一个假设并截图 / 输出日志
- 给"如果 A 则 X、如果 B 则 Y"的决策矩阵
- 第一次猜错立刻进系统化模式

详见 `memory/feedback-systematic-debugging.md`。

## Examples

### 正确
> 飘字 view 池：拿 → 用 → 还，0 GC

### 错误
> 每次受伤 `new Node()` + `addComponent(Label)` → GC 抖动

## AI Notes

- AI 优化代码必须先 profile 给数据，不能"我觉得这样更快"
- 不要把"性能"作为重构的借口（重构必须先达成共识）

## Checklist

- [ ] 60 FPS 目标场景达成
- [ ] 包体红线未破
- [ ] 池化关键短命对象
- [ ] 启动 ≤ 5s
