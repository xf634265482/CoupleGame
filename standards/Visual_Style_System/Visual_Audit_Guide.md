# Visual_Audit_Guide — 视觉审计与回归证据

## Purpose

建立可追溯、可比较、不会失控膨胀的视觉审计方式。

## Standards

### 1. 审计版本

- 每轮审计使用唯一版本号和日期。
- 记录审计范围、构建版本、设备和分辨率。
- 历史结论保留，不删除。

### 2. 必备截图

- 大厅。
- 命运树。
- 远征角色位于地图顶部、中部、底部。
- 普通战斗与 Boss 战。
- 核心弹窗。
- 涉及改造的关键状态。

### 3. 问题记录

每个问题必须包含：

- 截图或对照图。
- 设备与分辨率。
- 对应 VSS 条款。
- 严重级别。
- 问题描述。
- 建议处理。
- 当前状态。

### 4. 回归

- 改造前后使用相同场景、角色位置、设备比例和状态。
- Gold Standard、重大 UI 更新、背景更新必须做视觉回归。
- 只保存支持结论的关键证据，过程废图不进入正式审计包。

### 5. 严重级别

| 等级 | 定义 |
|------|------|
| P0 | 风格分裂、玩家/文字/危险信息不可读、关键布局漂移 |
| P1 | 主要层级错误、交互物难找、章节身份错误 |
| P2 | 装饰、间距、局部材质或轻微一致性问题 |

## Examples

正确：同一真机、同一角色位置，对比修复前后玩家尺寸与固定战场窗口。

错误：只写“感觉好多了”，没有设备、截图和规范依据。

## AI Notes

审计必须以证据为基础，不允许仅凭主观印象关闭问题。

## Checklist

- [ ] 版本与设备信息完整
- [ ] 关键截图齐全
- [ ] 每个问题引用 VSS
- [ ] 改造前后状态一致
- [ ] 历史结论保留
