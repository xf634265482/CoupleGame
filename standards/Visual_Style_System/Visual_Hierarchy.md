# Visual_Hierarchy — 视觉层级

## Purpose

定义"画面上谁该最先被看到、谁该让位"的优先级，让玩家在 1 秒内读懂"我现在该关注什么"。

视觉层级 = **注意力管理**。它决定 HUD 是否压角色、Boss 是否压玩家、宝箱是否压小怪、UI 是否压玩法。

本文件的核心是把抽象的"视觉重量"翻译成**可计算的层级数 + 可对照的工具**。

---

## Standards

### 1. 层级总表（Hierarchy Tiers）

> 数字越大优先级越高。

| Tier | 角色 | 示例 | 视觉重量手段 |
|------|------|------|--------------|
| **T7 Apex** | Apex Boss（章末终极 Boss） | 第 5 章命运裁决者 | 巨型剪影 + 独特轮廓 + 强 rim |
| **T6 Boss** | 章节 Boss | 第 2 章流沙巨蝎 | 大体型 + 加粗描边 + Boss 底光 |
| **T5 Elite** | 精英怪 / 关键 NPC | Elite 哥布林萨满 | 大于普通 + 微章节 rim |
| **T4 Hero** | 玩家化身 | 棕发蓝金冒险者 | 青色命运标志 + 居中可读剪影 |
| **T3 Common Threat** | 普通怪 | 章节普通怪 | 中等剪影 + 章节家族色 |
| **T2 Interactive** | 宝箱 / 道具 / NPC / 楼梯 | 宝箱 / 楼梯 | 强描边 + 暖光点 / Cyan 提示 |
| **T1 Field** | 装饰物 / 场景实体（非交互） | 残柱 / 火把 | 描边 60% / 饱和 -30% |
| **T0 Ground** | 连续棋盘 / 远景 / 背景 | 半透明战场平面 | 低对比格线 / 饱和最低 / 低细节 |
| **HUD** | 战斗 HUD / 顶层 UI | HP 条 / 飘字 | 独立层 + 强对比 + 安全区固定 |

> **关键**：T2 > T1 是因为玩家要先看"能交互的东西"再看"装饰"。

### 2. 层级工具（Hierarchy Tools）

> 同一画面里要把高 Tier 抬上来、低 Tier 压下去，可用的工具如下。

| 工具 | 操作方向 | 用法 |
|------|---------|------|
| **剪影大小** | T 越高，剪影面积越大 | Boss 占屏面积 ≥ 玩家 1.5× |
| **描边粗细** | T 越高描边越粗 | Boss +15~20%；T1 -40% |
| **饱和度** | T 越高饱和度越高 | T0 / T1 主动降饱和 30%~50% |
| **对比度** | T 越高内部明暗对比越强 | T0 平、T6 强 |
| **章节 Rim 光** | 仅 T5+ 使用 | 见 `Lighting_Guide.md` §6.1 |
| **底光 / 微震痕** | 仅 T6/T7 使用 | Boss 脚下微弱发光 |
| **色彩跳出** | 高 Tier 用章节强调 / 危险色点缀 | T6 加 10% 危险红 |
| **细节密度** | T 越高内部细节越丰富 | T0 几乎无细节 |
| **运动暗示** | 高 Tier 可加微姿态、低 Tier 静止 | T6 站姿张开、T1 静摆 |
| **位置中心** | 高 Tier 居中、低 Tier 靠边 | 玩法画面 Boss 居中 |

> 任何"想让某元素更突出"的诉求都**只能从本表挑工具**，不允许自创（如加发光特效 / 加帧动画）。

### 3. 100px 可读性测试（Phone-First Readability Test）

> 落实 Pillar 1 的最终关卡。

| 步骤 | 操作 |
|------|------|
| 1 | 把待评估资产 + 同章节锚资产并排 |
| 2 | 缩到 64 / 96 / 128 px 三档 |
| 3 | 由 3 人（或 3 个独立 AI agent）做 1 秒识别测试 |
| 4 | 通过 = 任意尺寸下能正确回答"这是谁 / 这是什么 / 危险等级"三问 |

**不通过的常见原因 + 修复手段**：

| 症状 | 原因 | 修复 |
|------|------|------|
| 100px 下糊成一坨 | 装饰过密 | 删 30~50% 次级细节 |
| 同章节小怪分不清 | 剪影家族无差异点 | 加个剪影记忆点（§ Shape_Language §5.2）|
| Boss 不如玩家显眼 | 玩家色更跳 | 加 Boss 体型 + 危险红点缀 |
| HUD 被角色压住 | 安全区不足 | 重新布局，HUD 独立层 |

### 4. 同屏分配规则（On-Screen Allocation）

> 当多个 Tier 元素出现在同一画面，按以下规则分配视觉空间。

#### 4.1 战斗画面（玩家 vs 普通怪）

```
T4 玩家（左 1/3）  ←→  T3 怪物（右 1/3）
                中央留 1/3 空间给战斗反馈（飘字、闪光）
HUD 顶部 12% + 底部 20%
```

#### 4.2 Boss 战画面

```
T6 Boss（屏幕中上 50%~60% 面积，居中）
T4 玩家（屏幕下方 20% 面积，正下）
HUD 顶部 12%（Boss HP 条另列在 Boss 下方）+ 底部 20%
```

#### 4.3 探索画面

```
T0 地图（70% 屏幕面积）
T2 交互实体（地图内突出）
T4 玩家（地图内居中）
T3 怪物（地图内分布）
HUD 顶部 12% + 底部 20% 行动区
```

#### 4.4 弹窗 / 结算画面

```
模糊层（虚化玩法）
T6+（如奖励物、Boss 立绘）在弹窗中央 50% 区
HUD 隐藏 / 半透明
```

### 5. 跨章节一致性

不同章节即便主色不同，视觉层级关系**不变**：

| 章节 | 玩家 Tier | Boss Tier |
|------|---------|---------|
| 第 1~5 章 | T4（不变） | T6（不变） |

> 玩家永远是 T4，不会因为"第 5 章末"被压成 T3。Boss 永远是 T6，不能因为"剧情需要"被低于玩家。

地图单位建议占格：玩家 75%~82%，普通怪 62%~72%，Elite 82%~92%，Boss 105%~125%。玩家真机清晰可辨高于整张地图同时完整可见。

唯一例外：**剧情演出帧**（如开场动画）可临时调整，但**不进入玩法画面**。

---

### 6. UI / HUD 优先级

UI / HUD **独立**于玩法层级，但有自己的内部 Tier：

| UI Tier | 内容 | 视觉特征 |
|---------|------|---------|
| U4 全局 Toast / 错误 | 顶层 | 高对比 + 危险色 |
| U3 模态弹窗 | 中层 | 模糊背 + 居中 |
| U2 HUD（HP / MP / 行动按钮） | 常驻 | 固定位置 + 中等对比 |
| U1 装饰条 / 章节名 | 弱常驻 | 低饱和 + 半透明 |
| U0 背板 | 底层 | 弱光照 + 不抢戏 |

**冲突规则**：玩法画面 + UI 同时争注意力时，**HUD 永远不让 Boss 完全消失**；Boss 大招特效不允许遮挡 HP 条。

---

### 7. 视觉重量违规对照表

| 违规 | 现象 |
|------|------|
| Boss 视觉重量 ≤ 普通怪 | "为什么这关感觉没 Boss" |
| 玩家视觉重量 ≤ 怪物 | "我玩起来不知道自己是谁" |
| 装饰物视觉重量 ≥ 交互物 | "宝箱我没看到" |
| HUD 视觉重量 ≥ 玩法 | "画面像 UI 套了游戏壳" |
| 章节 Rim 用在 T3 普通怪 | 视觉层级混乱 |
| 同章节多个怪物视觉重量相同 | 战斗节奏单调 |

## Examples

### 正确：第 2 章 Boss 画面层级
> T6 流沙巨蝎：屏幕中央占 55% 面积，外描边 +15%，沙尘底光 + 青色晶体 rim
> T4 玩家：屏幕下方 18% 面积，居中
> T0 场景：连续低细节平台，普通格线低对比，无实体粗描边
> HUD：顶部 HP/MP 12% + 底部 攻击 / 卷轴 20%
> → 1 秒内玩家能识别"我是谁、敌人是谁、危险在哪"

### 错误：装饰胜过宝箱
> 场景画了一个超大火把（T1）+ 一个小宝箱（T2），火把比宝箱大 3 倍
> 违反 §1 表（T2 > T1）+ §7 第 3 行
> 修正：缩小火把、放大宝箱、加 Cyan Magic 微光提示

### 错误：HUD 抢戏
> HUD 用了高饱和橙色 + 大字 + 装饰花边
> 违反 §6 U2 中等对比要求
> 修正：HUD 降饱和、简化、改用 §6.1~U2 视觉特征

## AI Notes

- AI 接到画面 / 资产任务时，**先列出涉及的 Tier**（"这是 T6 vs T4 战斗画面"），再开始设计
- 任何"我想让 X 更突出"的需求，**只能从 §2 工具表里挑手段**，不允许加新工具
- 100px 测试（§3）必须真实做，不许跳过
- §5 跨章节一致性是反"剧情需要乱抬层级"的硬规则
