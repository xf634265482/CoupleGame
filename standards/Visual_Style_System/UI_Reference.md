# UI_Reference — UI 视觉语言

## Purpose

定义《命运之塔》唯一 UI 视觉语言。行为与布局实现走 `standards/05_UI/`，视觉裁决以本文件和 `Visual_Style_Baseline.md` 为准。

## Standards

### 1. UI 定位

UI 是深海蓝绘制式幻想界面：

- 半厚涂软斜面。
- 深海军蓝主体。
- Deep Navy Charcoal `#17243A` 清晰轮廓。
- 青色命运内光。
- 柔金关键边饰。
- 与角色和世界使用同一光照与材质语言。

它不是毛玻璃、现代扁平 UI、Material Design、iOS Glass，也不是厚重石框 MMORPG UI。

### 2. 透明度

| 区域 | 不透明度 |
|------|----------|
| HUD、战报、持续阅读区 | 88%~95% |
| 弹窗主体 | 92%~98% |
| 装饰条、非阅读区 | 65%~80% |
| 按钮主体 | 接近不透明 |

禁止真实背景模糊。通透感通过手绘层次、色差和内光表达。

### 3. 文字

- 所有持续阅读文字必须位于安静底色上。
- 正文、数值、按钮使用中粗圆角无衬线。
- 短标题可使用轻度奇幻展示字体。
- 核心按钮、HP/AP、关键数值 24~28。
- 卡片标题、怪物名称 22~24。
- 战报正文、常规资源 20~22。
- 辅助信息 18~20，禁止更小。
- 长文本用精简、换行或滚动解决，不缩字硬塞。
- 正常握持距离阅读吃力即判定失败。

### 4. 按钮层级

| 类型 | 视觉层级 |
|------|----------|
| 攻击/主行动 | 最高对比，青蓝或章节危险色强调 |
| 互动/常用行动 | 蓝金次级样式 |
| 结束回合 | 清晰但降低饱和，避免误触 |
| 返回/角色/低频入口 | 视觉重量较轻，但尺寸与文字仍清晰 |

- 可点击区域不得小于约 76×76 设计像素。
- Pressed 约 0.08~0.15 秒压缩回弹。
- Disabled 降低饱和和亮度，但文字仍可读。
- 不单靠颜色表达状态。

### 5. 图标

- HUD 与状态图标在面板上使用独立图形，不重复套厚框。
- 道具、装备、技能使用统一圆角框。
- 按钮图标与按钮一体。
- 单一语义，最多三组主色。
- 32 px 可辨大类，48 px 可辨具体功能。
- 数字、数量、稀有度文字由代码叠加。

### 6. 装饰

- 装饰集中在四角、标题节点和重要状态锚点。
- 阅读区保持安静。
- 青色晶体、柔金纹章和星尘是品牌签名，必须克制。
- 常规面板最多一个主要装饰主题，重要弹窗最多两个。
- 装饰不得侵入文字安全区、点击区和进度条。
- 真机不可辨认的细纹、花边和铆钉删除。

### 7. 弹窗

所有弹窗共享统一骨架，只改变强调层：

| 类型 | 强调 |
|------|------|
| 普通确认 | 青蓝 |
| 奖励/结算 | 柔金、少量星尘 |
| 危险/死亡 | 珊瑚红、低饱和紫灰 |
| 强化/职业 | 青色命运晶体、职业色 |
| 商店/铁匠 | 暖金、浅铜、温暖木色 |

禁止为不同功能重新设计第二套边框体系。

### 8. HUD 信息流

- 顶部第一层：章节、楼层、回合、碎片。
- 顶部第二层：当前怪物卡约 60%，资源区约 40%。
- 战场下方：最近战报与玩家状态约 6:4。
- 底部：左列低频入口、中列方向键、右列战斗动作。
- HUD、战场外框、战报和操作区固定，不随玩家移动。
- 无怪物时怪物卡保持尺寸，禁止布局跳动。

### 9. 战报

- 常驻显示最近 2~3 条高价值事件。
- 伤害、获得、状态、危险使用固定图标和功能色。
- 连续同类事件可合并。
- 完整历史通过滚动或展开查看。
- 当前重要事件可短暂提亮，不持续闪烁。

### 10. 禁止

- 真实毛玻璃和背景模糊。
- 现代扁平、Material Design、iOS Glass。
- 厚重石框和密集装饰。
- 文字直接压在场景、粒子或复杂纹理上。
- 通过缩小字号塞入内容。
- AI 生成带真实文字的完整 UI 截图作为资产。

## Examples

正确：战报使用 92% 不透明深海蓝面板，正文 20~22，中粗象牙白；角落仅一个柔金命运纹章。

错误：透明玻璃面板覆盖高亮云海，使用细灰字和大量金边花纹。

## AI Notes

- UI 的第一目标是 effortless reading。
- “次要”不等于难看清、难点击。
- 视觉和阅读冲突时，无条件优先阅读。
