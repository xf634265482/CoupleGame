# UI_Rules — UI 通用规则

## Purpose

定义 UI 必须遵守的通用行为规则。

## Standards

### 1. 构建方式

- **代码构建**：所有 UI 在 `views/` 中由代码组装；不依赖 prefab
- 工具函数命名 `xxxLayout.ts` / `pveUiKit.ts`
- 复用 `UiAssets` 加载 SpriteFrame

### 2. 三态原则

任何可交互元素必须有：
- Normal
- Pressed / Hover
- Disabled

### 3. 反馈即时

- 任何点击必须 ≤ 100ms 内有视觉反馈（按钮下沉 / 飘字）
- 网络等待 > 500ms 必须显示 Loading
- 网络失败显示 Toast + 重试按钮

### 4. 单手可达

- 关键按钮在屏幕下半部
- 屏幕顶部只放 HUD / 标题 / 关闭按钮
- 不在底部最底 5% 区域放可点击元素（避免误触系统手势）

### 5. 文字与可读

- 核心按钮、HP/AP、关键数值：24~28 设计像素，加粗
- 卡片标题、怪物名称：22~24，加粗
- 战报正文、常规资源：20~22，中粗
- 辅助信息：18~20，禁止更小
- 行间距 ≥ 1.4
- 所有持续阅读文字必须位于高对比安静底色上
- 长文本通过精简、换行或滚动解决，禁止缩字硬塞
- 正常握持距离阅读吃力即判定失败

### 6. 弹窗层级

> 见 `Popup_Guide.md`。

- 同时只允许 1 个主弹窗 + 1 个 Toast
- 错误优先；玩法弹窗按队列

### 7. 不允许

- ❌ 阻塞主线程的同步操作
- ❌ 无反馈的"点了好像没反应"按钮
- ❌ 关键按钮在屏幕顶部
- ❌ 弹窗叠 3 层

## Examples

### 正确
> 攻击按钮：Normal → 点击下沉 4 px + 0.05s → 触发战斗

### 错误
> 攻击按钮：点了没动效 → 玩家不知道有没有点上 → 连点 → 多次结算

## AI Notes

- UI 状态必须用 `_busy` 守卫并发输入
- UI 行为不写进 view 层之外

## Checklist

- [ ] 三态齐全
- [ ] 100ms 反馈
- [ ] 关键按钮在下半部
- [ ] 没有同时 3 层弹窗
